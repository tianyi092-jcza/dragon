## 固定输入与复核

新工具 `tools/audit_editor_neutral_initialization.py` 只读项目父目录的上／中／下／后／原版五个固定 `SINARIO.DAT`，逐文件核固定SHA及长度，无路径参数、glob、SAVE访问、解析器导入、补尾、KI执行或文件写入。stdout由命令重定向到自有分析目录。输入SHA沿已核固定源，并重新实际检查；不是使用Web生成JSON反证原数据。

每章按**文件偏移**分区（状态段起点为章+80h）：头0..80、势力80..680、外交680..8C0、城市8C0..20C0、地图对象20C0..22C0、军团22C0..42C0、武将42C0..52C0、事件52C0..56C0。输出记录宽度、期望／实有长度、完整记录数、缺失槽、非零槽及实有部分SHA；未激活普通将另列全32B的非零偏移与SHA，G127和非正常势力槽22／23独立保留，不按公开数量裁去。

复核命令：

```sh
python -X utf8 -B tools/audit_editor_neutral_initialization.py
python -X utf8 -B -O tools/audit_editor_neutral_initialization.py
```

本批两个输出 `.dragon-analysis/editor-completion/neutral-init-inventory-{r2,optimized-r2}.json` 逐byte一致，20章、160表切片、5项内存自检（完整全零／短尾／缺表／非零记录／连续分区）。检验使用显式异常，不受`-O`移除assert影响。r1是未加残值汇总的成功版本，保留；新增zip缺strict的静态诊断在首次运行前改为两段等长、`strict=True`，未屏蔽。

## 后继KI读取长度与返回标志静态链

`audit_editor_scenario_read.py` 只读SHA固定的 `Dragon/KI.EXE`（`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`），核MZ头200h、9个精确指令签名及3个完整对齐窗口。它不执行KI、不调用DOS、不读取任何SINARIO／SAVE，也不提供路径参数；输出为可复核原始字节和16位反汇编。

**实锤（限定指令链）**：

1. `8CAE..8CFE` 以AL乘56C0h作为文件偏移，三次调用 `E38C`：章+0读取3Bh到CS:CF0，章+80h读取5240h到[D52]:0，章+52C0h读取400h到[D56]:0。这里没有填充缺失尾字节的指令。
2. `E38C..E3A5` 保存调用方寄存器，调用 `F4DF` 后恢复，再以 `JAE E3A5` 决定返回；另一分支为 `INT50` 后重试。此包装层不比较字节数。
3. `F4DF..F527` 的正常打开／定位后路径执行 `AH=3Fh; CX=DI; INT21`，随后没有把返回AX与DI／请求长度比较。尤其不能把 `F513 LAHF` 当作可靠保留读取标志：紧接着 `F514 MOV AH,3Eh` 已覆盖AH，关闭调用后 `F51B SAHF` 使用的是**关闭返回后的AH**；`F521/F526 LAHF/SAHF` 才把该重建标志保留至返回。因此包装层看到的CF由关闭返回AH的bit0重建，不能直接说它就是DOS读取CF。

**条件结论**：在打开／定位正常、关闭返回AH相同的条件下，不同的读取返回字节数会经过相同后续路径；这不是实际DOS短文件行为证明。关闭返回寄存器、事件缓冲的分配所得字节及后续写入前史、INT50及打开／定位失败路径的完整行为仍未知，缺失2B仍未知。不能据此补零、默认清事件轮或撤掉完整导入长度门；G-INIT未放行。

复核：`python -X utf8 -B tools/audit_editor_scenario_read.py` 与加`-O`输出一致，证据 `.dragon-analysis/editor-completion/scenario-read-chain-{r2,optimized-r2}.json`。固定源截断及9个签名起点分别翻一bit共10个损坏源拒绝（`scenario-read-chain-negative.log`）；非法参数拒绝且stdout空。首轮r1／optimized-r1的字节窗口正确，但解释错误称LAHF保留读取标志，**该解释明确作废**；人工逐指令重核发现AH覆盖后已修为上述r2，没有据旧解释修改产品。早期探索从8C80未对齐起点解码的输出未进入本证据；正式窗口从8CAE入口开始且全部解码长度精确。
