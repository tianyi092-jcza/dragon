# 行军显示与战略节奏修正

本轮用户要求：到城不再额外横/纵挪动、接战快速五响、战略提速、消除行军走停；保持全骑兵速度优势。以下显示/音频/墙钟选择是 **Web 产品决定，不是 DOS 原始显示或毫秒时序**。

## 原始证据复核

只读 `Dragon/KI.EXE`，SHA256 `fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`，文件偏移 = VA + `200h`：

- `6FD2..7003`：CL=6，逐队读 `type(+2)`；任一不是1就置CH=1，循环后CH++，比较扫描末BX与012Ch后再CH++，写L1E。合法固定军团槽的BX必大于012Ch，因此六队全type1周期2，否则3。兵力0的队也检查兵种；BX不是总兵力。
- `25A3..25D8`：每批16槽；活动槽先DEC L0B，非零跳过动作；零则从L1E重装、清status bit5、调用2662，再日结与264A尾。128槽一轮8次主更新；连续正常行军的两次动作分别间隔16/24次更新。相同直路上纯骑速度是混编的1.5倍，不是另加Web兵种加速。
- `27A2..27E9`：选edge端点写L0E，城市节点取城X/Y写L10/L12，再写占格指针。节点切换本身不生成额外Web像素修正。
- `2B2A..2B38`读同一L10/L12交给D4C7；`D4C7..D4F1`减视口格坐标后定位图块记录。原版这里没有Web的“横路+3Y、竖路+2X、驻止归零”分支。完整绘图下游仍沿既有证据，不把本窗口宣称为全VGA认证。

## 已定位的Web问题与修复

1. **锚点不一致**：`roadVisualOffset`只给移动/有下一点的军团补偿，`cityPixel`及驻止用格中心。军团逻辑已到城时仍保留方向偏移，下一动作prev清零才消失。统一城标、行军、驻止、拾取与接战图使用 `(16*x+10,16*y+11)`。保留旧横路Y+3、竖路X+2标定，但变为统一平移；道路资产、规则坐标、到达条件不变。弯道不再因换方向跳补偿。此为可逆美术选择，不声称DOS也加这两个偏移。
2. **插值时长少算**：原只除8，纯骑每步动8次更新后停8次，混编停16次。现除 `8*movePeriod`，使用既有权威周期而非重新猜兵种。无相位的独立预览保留旧单周期兼容；正式规则不会因此补字段。每段线性移动覆盖完整动作间隔，绘图不写规则/RNG/路线；不预测尚未提交的道路点。斜线距离及节点/命令等待仍按原规则，不为绝对像素等速改变每步规则时间。
3. **接战声无上限**：旧120ms一直重触发，“顶速约五下”只是接触时长巧合，不是次数保证。现一段连续共享接触最多五次请求，正常节拍在0/60/120/180/240ms发声；30ms换帧。暂停、目标对象刷新、新增重叠军团不重置共享预算，也不叠声。接触提前消失/切场景立即停止，不为凑足五下延后战斗或补播；丢帧每RAF最多请求一次、音频未ready也不形成积压。画面继续显示有效接触，五响后不改变规则等待。
4. **战略墙钟提速**：五档从 `120/70/40/20/6.25ms` 改为 `60/35/20/10/3.125ms`，每RAF上限从3到6，60Hz可容纳顶速预算。逐步检查hold、后台不补债，完整主更新内部顺序、日历、RNG、六队周期及战术速度不变。理论顶速连续单步纯骑50ms、混编75ms；实际受RAF/计算负载/hold影响，不承诺固定设备帧率。

## 插值朝向与图片就绪（出城／转弯／到城补正）

后续反馈为大城出发闪烁、提前转向与提前显示驻守。已复核两条独立的Web显示路径：

- `getMarchMarkerImage`首次请求某样式/方向时返回null，`_drawMarchingIcon`直接不画。现地图资源安装前等待24样式×5帧全部加载回调，避免正常资源下首次换帧空白。沿现有资源策略，加载失败会结束等待而非永久卡住；不声称能让缺失/损坏资源正常显示。
- `getLegionRenderPos`的位置在prev→current之间，旧代码却立即采用current的`_markerFrame`。原码`27E9..27F1`比较L0E/L14，相等就写L8=4；`2808..2830`从L0C+stride的道路点计算方向。这些是已提交规则状态，不能提前用于仍在旧段途中的Web插值图标。现`curT<1`时只按正在显示的prev→current段定向，段完成后才采用规则帧。到达时刻、路线、+8字段、RNG和骑兵周期均不改。此为Web表现合同，不宣称DOS也有这套插值。

验证：`verify_march_marker_presentation.mjs`覆盖四方向、周期2/3、所有后继帧、延迟图片加载屏障与120帧首次绘制；`verify_march_markers_browser.mjs`以全新profile核实际120张PNG就绪，并在正式MapView中使用许昌坐标的隔离显示fixture逐tick核出城始终有图、入城段未完不驻守、段尾才变帧。该fixture不是完整原版行军轨迹证明。

## 验证范围

- 原字节复核只认证上述周期/坐标消费者；Web回归锁定输入不变、显示连续与音频上限，不替代原版全战役对照。
- `verify_march_navigation.mjs`覆盖横纵双向及斜向、周期2/3完整插值、到城/驻止锚点一致、只读投影。
- `verify_engagement_presentation.mjs`与隔离浏览器覆盖五档、五响上限、共享通道、暂停/恢复、取消、音画相位及无RNG写入。
- `verify_clock_transition.mjs`覆盖新档位、单RAF上限、即时hold及日历边界；原生编成/槽/道路套件继续检查周期和规则。
- 本轮实际完整回归、诊断限制与证据目录另记[checkpoint journal](checkpoint-journal.md)。历史100/200ms、60/120ms“响满全程”与八更新插值摘要均由本文取代，原始DOS音效次数仍为纯骑五次/混编三次，不混为Web五响政策。
