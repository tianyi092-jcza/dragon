## 1. 可复跑证据

仓库根执行：

```bash
node tools/audit_system_base_map.mjs <new-round>
```

只接受字母数字/连字符轮次，输出到全新 `.dragon-analysis/system-base-map-<new-round>/`；存在即拒绝，输入只读，不读取DOS SAVE、数据库或用户profile。工具调用 `readInstalledEditorSource`，核38资产SHA/大小、批准标记、sourceDigest、20章身份及共同编译出的terrain/roads/roadCost/roadOffset一致性，不放宽原准入。

源盘点首批收据为`system-base-map-b0-r2/`、`system-base-map-b0-r3/`；非水候选扩展收据为r4/r5；据点跨层检查后的当前收据为`system-base-map-b0-r6/`、`system-base-map-b0-r7/`，七项工具产物逐字节一致：

- `ownership.json`：按 `y*384+x` 索引的98,304格归属，记录实例、层、所属道路/据点及定义。
- `review.html`：无脚本/网络的本地审阅资料，含256种编号图样和8个局部样本。**不是编辑器产品页面，也未进行浏览器视觉验收。**
- `atlas.png`、`map.png`：当前已登记春季图集和全图的只读副本，供离线样本定位。
- `candidates.json`：全部69,786个非水装饰的四邻接候选片、逐格成员、包围盒；建筑候选另列最近三个据点及距离，不自动归属。另含192据点5×5跨层检查窗、字节/层签名和窗口外异常格；窗口不是正式footprint。
- `candidates.html`：候选统计、每类最大三片及全部467片建筑候选的可展开原图/成员标记。四邻接仅缩小审阅范围，不是正式语义对象。

最终离线页：[B0图样与成员样本](../.dragon-analysis/system-base-map-b0-r2/review.html)。产物为本地ignored证据，未随源码提交；其它机器按上述命令重建，不依赖该临时目录运行产品。

## 2. 全图覆盖

| 项目 | 本轮实测 | 含义 |
| --- | ---: | --- |
| 地图 | 384×256＝98,304格 | 每格16px；没有扩容 |
| 原子定义 | 256种，实际使用238种 | 全为单格`atomic-original`，不是256种完整创作对象 |
| 装饰格 | 92,586 | 含水域、地面、山地、田地及部分建筑外观 |
| 道路 | 254条／5,526格 | 每条geometry与components逐点相同 |
| 据点放置 | 192个／192格 | 和城市主表坐标逐项相同，原运行槽唯一 |
| 格归属 | 缺失0、重叠0 | 装饰＋道路＋据点正好覆盖全部格 |
| 底层 | 98,304个null及对应unknown记录 | 不是空白可随意填入，也不是已知草地 |
| 水域组 | 161组，51组小地图显示 | 既存Web作者组合，不是DOS水文对象 |
| 水域覆盖 | 23,716个不同格 | 22,800个带waterClass装饰＋916个道路底部显示标注 |
| 无水域组的非水装饰 | 69,786格 | **尚无语义对象分组，不能当完整转换完成** |
| 道路显示标签 | 陆219、水35 | 标签不是原flags、代价或移动规则 |

**水域的双引用不能重复计数**：916个道路水域格同时存在于组的`memberIds`（道路图块）和`baseCells`（地理显示标注），应计一个物理格；道路图块本身不必有`waterClass`。本轮工具首跑错误地要求所有成员都带该字段，断言失败；核对 `map_minimap_groups.mjs` 与 `maplayers.js` 后修正，未修改源数据或编译器。完整水域组覆盖与独立成员校验现已通过。

带`waterClass`的装饰为海9,806／河12,341／湖653；这不是包含916格道路底部标注后的全图分类总数。水域旧来源里的`CATEGORY_APPROVED_VISUAL_PENDING`是冻结来源文本，当前登记批准由manifest核验，不能静默改旧源文本。

## 3. 全图元素分类与编辑粒度

下表是本批编辑设计边界，**不是当前UI已支持列表**。正式配方仍只用受信`ki-byte-stamp-1`保存显式tile字节，不能按名称/像素重新推导规则。

| 元素 | 当前表示 | 创作/选取粒度 | 移动、删除与组合边界 |
| --- | --- | --- | --- |
| 基础地面 | 原图可见地面也在装饰层，base全部unknown | 显式基础格/刷选区域；是否将纯地面下沉为base须记录逐格映射 | 只写作者明确选定图块；不得把隐藏底层一律补草。下沉会影响层归属及选择，未自动执行 |
| 山脉/丘陵 | 单格不透明图块，没有完整山体身份 | 多格可复用片段＋明确成员组合；长山脉须可拆，不是一整个不可编辑背景 | 位移保留相对格与顺序；删除暴露unknown则阻止生效，允许作者明确补底后再检验 |
| 草地/田地等装饰 | 图样和原子，没有独立完整对象定义 | 明确单格笔刷与多格田块/纹理片段分开；不能所有图样都强拼成大对象 | 同上；组合不推断所属据点、生产力或规则地形类别 |
| 河/湖/海 | waterClass＋161个明确组，含道路底部显示引用 | 保留现有组身份/成员与显示开关，允许编辑核心提供选择/拆组 | 显示开关不动大图/规则；水域组不是跨层整体移动许可，不可拖河流时捎带改变道路拓扑 |
| 道路/桥 | 整条边、原槽/tag/flags/成本/geometry＋逐格外观 | 一条拓扑边与其视觉片段分开；桥是图样候选，不自动建立水路 | 本期不开放未证拓扑变更；删除/移动/重连不能仅改图片或按颜色重算。选择/查看可以独立实现 |
| 据点 | 原槽/主表身份＋单格放置；周边建筑图样仍可能在装饰层 | 据点实体和多格外观附属片段分开，外观不产生新据点 | 不增减192槽；坐标修改须走主表统一入口及道路绑定检查。未证移城运行不开放，不能复制图样即创建新槽 |
| 长城/城墙/关隘等建筑图样 | 仅图块外观，未辨完独立片段与据点附属关系 | 逐处审查后形成多格片段，转角/端点/门等显式变体 | 不从外观推防御/战术入口；不自动旋转规则字节，不自动把相邻墙全部并为一个对象 |

全格物理归属已经明确；下表记录早期盘点，现行Web分片粒度见§4.3，不要求猜测DOS自然对象边界。图样、规则字节、拓扑、显示水域是不同维度，分类不得覆盖或删除其中任何一种信息。

### 4.2 逐城跨层检查与当前产品边界问题（r6/r7）

192据点全部输出5×5检查窗；按检查窗内编号≥184的`相对坐标/tile/层`精确比较，共102种签名。这是当前源的重复图样统计，不是102种原版城型或可运行城市定义。窗口内覆盖1,348个建筑装饰格；无装饰格同时落入两个据点检查窗。

与§4.1距离候选比对还差4格：city-031旁的28229(tile224)、28230(tile249)，city-068旁的38943(tile251)，city-072旁的42056(tile250)。r6的辅助PNG `city-exceptions.png` 直接审阅可见关口/墙段延伸超过窗口；city-031还包含转折。**不能用统一5×5截取城市外观，更不能按最近距离将整个墙段认定为城市附属**。192检查窗及原成员可由同一工具重建，不将临时PNG当原机制证据。

到这里原资料和当前源已能保证逐格保真，但不能唯一给出“哪段山脉/田块/墙体应为一个默认创作组件”。既有设计禁止把自动连通结果直接当正式语义对象；这不是继续编译或追野战公式能解决的问题，是首版编辑粒度的产品选择。可选方案：

- **建议A：Web可拆编辑片段**。明确允许以可复核的视觉候选生成首版片段；超过现有素材256格上限的片拆成局部片段，保留上层组合及逐格溯源，管理员可以拆/并/重组。不宣称恢复原版对象身份。地面维持显式笔刷/格，未知下层不补。城/路保持原实体，跨层外观只存选择引用，不赋予整体移动或改拓扑权限。具体分片策略/样本在获准后落成独立可复跑合同，不悄悄加入规则。
- **B：先人工明确全部自然对象边界**。候选只作审阅，管理员确认成员后才转换；这需要实际作者审阅输入，不能以当前102种签名或四连通结果代替。

**用户已明确选择A，解除本节此前的产品选择阻塞；B未采用。** B0按下节可拆片段合同验收，不再等待人工判定全部自然对象身份。独立的B1前置接缝审计见[设计§7.1](system-base-map-design.md#71-b1前置接缝核对部分完成未实施)，没有修改旧profile或来源门。

### 4.3 已批准A的初始Web分片合同（r8/r9）

`tools/system_base_map_pieces.mjs` 是只读规划器，由审计入口输出 `piece-plan.json`，尚不是持久化模板。策略 `web-piece-policy-1`：保留§4.1四种**视觉图样标签**和四连通上层组；按原点对齐的16×16格网切片，每个格网内再按四连通拆分，每片不超过256格。标签不作为规则地形，也不把全图同标签合成一个对象。每个片段保存源实例ID/格索引，定义保存完整footprint与逐格原byte配方；归一化相对坐标/byte相同者共享定义，不共享可变实例。

结果：69,786非水装饰格 → 4,081可拆组 / 5,506片段 / 2,101可复用定义；2,962片为多格，其余为确实孤立或格网切出的单格，最大片255格。规划摘要 `4d6763392ecc09b52c61eeb3a916379554218cda9a93d61158cecad5045d42a0`。每个输入格恰好出现一次；实际落入的原byte与源完全相同。分片边界是Web编辑决定，不是假称原版山脉/农田/城墙边界。

- **地面/岸线**：暂不自动下沉base；35,285格仍为可拆装饰片。仅显式作者补底才能改unknown，不能由邻格颜色猜底层。
- **山纹/田纹/墙与城边纹理**：片段为默认编辑粒度，上层组可多选/拆组/重组；不承诺未知底层处移动/删除后能够直接保存为有效模板。严格编译拒绝暴露unknown，编辑草稿可定位并补底。
- **水域**：保留161个既有组合及member/base双引用，覆盖23,716格（含916道路下的显示格）；初始不把水域组合铸成超大单定义，不重复计数道路底色。组合可选，不授予所引用道路移动权限。
- **道路与据点**：254道路保持各自有序组件/拓扑，192据点保持中心实体/运行槽；跨层选择引用与实体身份分离。附近建筑片不自动挂为据点附属，5×5审阅窗口不是footprint。完整城图的多层选择由作者显式建立，不能通过“选中组合”绕过固定槽/道路支持域。
- **全图归属**：上述69,786格 + 水域装饰22,800格 + 道路5,526格 + 据点192格 = 98,304格；底层98,304个unknown保留来源，不凭空补地。几何选择按真实footprint，不按包围盒吞掉孔洞或别层对象。

r8/r9八项正式产物逐字节相同。独立测试 `node tools/verify_system_base_map_pieces.mjs` 核确定性、输入不变、全部成员唯一/归属/byte、片段四连通/单格网/≤256、组合成员完整性及重复格/越界/扩容负控。辅助PNG直接审阅四类最大组：山纹39332=1,400格/24片、田纹244=96格/2片、墙纹4753=38格/3片、地面78=2,019格/23片；颜色边界明确为可拆Web片，不改变原视觉。辅助图不是浏览器验收或原版规则证据。B0清单/粒度出口闭合；该r8/r9阶段仅有规划，后继物化、编译与实际工作台证据见设计§7及实施清单，不将规划收据冒充产品验收。

## 5. 据点权威与能力边界

[据点合同](editor-city-definitions.md)规定：游戏共享主表拥有名称、坐标、类型、最大生产力及新章默认四值；章节保存所属/当前值等覆盖。模板只提供创建初值和稳定槽映射，游戏地图放置引用其主表，不拥有第二份可独立编辑坐标。当前源的`cities.x/y`与`placements.x/y`是相符投影，不能因此允许以后两处各自写入。
