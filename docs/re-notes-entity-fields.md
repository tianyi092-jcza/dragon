## 武将 1. 记录定位、初始化和索引边界

### 武将 1.1 基址不是文件偏移

`8B12→8CAE`选新剧本，`8CAE`以 `DX=D9A` 指向KI内字符串SINARIO.DAT。章起点为`chapter*56C0h`；先读头部，再在`8CCF`加80h，`8CD5`取`BX=[D52]`，`SI=0,DI=5240h`调用`E38C→F4DF`。`F4F3`把BX设为DS，DOS seek/read到`DS:SI`、长度DI。因此武将文件偏移确为`chapter*56C0h+80h+4240h+i*20h = chapter*56C0h+42C0h+i*20h`。

**所有32字节都参与初始化的批量读。** `8CFF..8D37`另有整个5240h状态段的批量输出指令，可仅凭KI静态证明其包含武将记录；本轮没有执行该I/O，也没有读取真实存档。未知字节不是可随意丢弃的“无持久化空间”。

### 武将 1.2 三类地址来源必须分开

- 通用原将：`index(byte)<<5 + 4240h`。常见用BH=index，BL=0，BX>>3实现。
- 军团槽别名：`((legionPointer-2240h)>>1)+4240h`；读`+16/+1F/+1E`的多处消费者走这个关系，**不先读军团+2**。
- 军团主将索引：`52DB`从`legion[+2]`得到武将索引；战术`9C13`从`D30A`临时军团记录+2读取（由`9E97 rep movsb`复制战略军团+1..+7）。

`6E8F/6F26`正常编成同时绑定同号军团槽与武将索引，故通常三者一致；自定义数据不能假定槽号和generalIdx永远可互换。

### 武将 1.3 128、127、126各有边界

|路径|真实范围/作用|

|`763C/76A0`武将列表/任官候选|从4240h每20h加到5240h，完整128条；但受attr/owner/status门控|
|`92F5`头像已用检查|`CX=007E`，126条，0..125，不检查active；不能宣称排除了所有普通将头像|

|`+1C/+1D/+19`中的FF|无当前属/无旧属/无预设目标，各自语境，不能当武将127|

自定义军师路径`8FC9`改`5221`，`905E/9075/911E`写`5222+SI`（SI受0..0A偶数限制），取消`8F7C`恢复头像FF及六个D0A1占位word。`9047`把势力军师索引写7F，`1B12`随后把所选军师记录attr整字节清零；若选择普通军师，则清的是该普通将，不是始终127。所以127“无军师”和“自定义军师”取决于名字/路径，不是单一语义。

**第三方“第127号自创军师”线索复核：** `8FC9`自定入口装入`END_S15.DAT`输入界面；`8FF8`检查`5221`头像、`8FFF`首次设91h，`9047 MOV BYTE [BX+2],7F`把所选势力的军师引用指向该条。取消路径`8F7C`还从势力`+3F`恢复默认军师`+02`。正式选择后，`1B00 CMP AH,7F / 1B03 JE 1B08`只跳过`1B05 DEC [BX+18]`，**没有跳过`1B12`清所选军师attr**；普通军师要扣将数，自创槽不扣。不能把“可以自定姓名/头像”扩大为“第127槽可作普通新增战将”，也不能覆盖其8/8/8能力而忽视`4F8A→52D7`临时城防消费者。

未见第128号（第129条）合法普通将入口。索引8位但大多没有防越界；未来剧本不能因8位存储就扩容到256或把FF传给通用武将寻址。

### 武将 2.1 每位解释边界

- 00 bit7/6/5/4分别上表实锤；bit3/2/1/0机制未知。第三章槽88张卫attr81，其他章0低nibble；没有依据说这1是错字，也不能擅自删。
- 0E..10 bit7..4整体作为无符号四位数使用；bit3..0在三条已核能力消费者中被右移丢弃，未找到低半字节单独使用证据。
- 11..13 bit7..0整体u8。不存在“低位为能力、高位是另一个隐藏属性”的证据；高位已参与数值比较/算术，不能划为未知空闲字段。
- 14/15/1B全8位未解；14虽然样本只0..7也不能把bit3..7宣布unused。
- 16/17/18/19/1A/1C/1D/1E/1F均已见整字节消费者或整字节写回；其位不是独立的编辑开关。枚举/计数/索引/派生的差异必须保留。
- 01与02..0D属于资源号与编码文字，全byte；Big5多byte原子性优先，不能按bit研究为AI属性。

## 武将 3. 关键机制与原始指令证据

所有VA均是KI文件偏移减200h；以下near-call目标按16位IP回绕，Capstone显示`ffffece0/101b4`时应读`ECE0/01B4`。反汇编必须从已知指令起点起跑，不能把任意窗口误对齐的输出当指令证据。

### 武将 3.1 派生评分+1F：初始化→消费者→重算

精确写回：`g[1F]=u8((g[0E]>>4)+(g[0F]>>4)+(g[10]>>4)+2*g[11]+2*g[12])`。能力为全byte，所有AH/AL中间结果按8位回绕；本式是其模256等价，不是无限整数评分。

#### 新局与标准DOS读档：差别不在是否进入55A6

#### 两次重算间的+1F权威性与保留约束

|边界|+1F处理|不能混淆的结果|
|---|---|---|
|8CAE文件块载入|原样恢复32B，包括1F|载入函数本身不保证值已派生正确|
|标准新局首入战略|55A6重算attr>=80且i<127|初始静态自定1F被覆盖；玩家选中军师attr已清零，跳过重算|
|标准DOS读档首入战略|同样55A6重算attr>=80且i<127|不能假定读档跳过重算；非活动/127原byte仍保留|
|普通战略帧中的4C72、291A|直接读存储1F，没有临时调用55A6|不能把消费者替换成每次依据能力现场计算|
|每月结|585F处理状态以后5391调用55A6|月结顺序是行为边界，不是每天或每场速算重算|
|战术回战略|1B7E调用533D，早于1BBA/1BC9的474A及后续去向|真战术结束会重算；战略5130返回不经此入口|
|8CFF原程序状态写出|整个5240块含1F，原样输出|派生字段确有持久化，不能据“可算公式”删除原始byte|

**储存状态示例（仅指令推导，不是动态测试）**：4CD0读取同号军团槽对应武将的1F，而4C72筛的是军团active，不检查武将attr；2960同样无武将attr门。若输入里武将inactive但同号军团active，标准读档55A6会跳过该将，所存1F仍可进入这些消费者。这说明数据格式可装入的不一致状态与普通合法剧本不变量必须分开；本字典不把这种不一致状态推荐为正常剧本，也不补兜底。

若未来受控剧情/工具在两次重算间写入该byte，或恢复的是中途内存快照，消费者将使用所存值，直到下一个实际55A6边界；这是现有读指令的必然后果，**不是本轮发现了某个原版剧情写入者**。已核独立运行写入者仍只有55DC，另有块载入；“剧情另写+1F”没有证据，不应凭监督提示或合理性添加。未完整闭合的间接代码可能另有写入，仍保持未知。

长期字典必须明确：+1F存储byte是该时刻的派生评分，既要记录原值，也要记录原始重算边界，不能只留下公式。本字典不决定Web存档schema，更不以“派生”授权删除快照字段。只有在指定合法状态范围、入口与后续可观察结果均证明可重建时，才可另外讨论去冗余。

#### 一般招募偏置与“刘勋九成”说法

第三方摘录“随机武将偏向少将势力”有原机制依据，但“第一章九成投刘勋”不能作为概率规则。关键窗口为`58C7 AX=FF16 / 58CF CMP AH,[DI+18] / 58D2 JB skip / 58D7 BX=DI`；`58E3 AND AL,3F / 58E5 INC AL / 58E7 CMP AL,30 / 58EB CMP AL,18 / 58EF MOV AL,1`造成非均匀落点。`5907..5918`是另一个玩家资格分支，不是继续循环抽势力。

```python
hits = [0] * 22
player_branch = 0
for r in range(256):
    k = (r & 63) + 1
    if k >= 48:
        player_branch += 1
    else:
        if k >= 24:
            k = 1
        hits[(15 + k - 1) % 22] += 1
assert hits[15] == 104 and player_branch == 68
assert sum(hits) + player_branch == 256
```

104个输入字节通过一般分支落到刘勋；另68个进入玩家资格分支，是否加入取决于玩家当前城数/将数/身份。选择普通军师的`1B05`扣数、后续武将加入和势力灭亡都会改变起点与循环。该枚举不是实机固定招募概率，也不证明每名在野将独立同分布。

对`+18/+19`的编辑约束仍按上面的控制流：倒数非零时先减、即使刚变0也跳过本月；预设目标灭亡且通过随机门控后，先清`+19`，未置attr bit5者下月才走一般招募，不能写成“永远只投预设势力”。

**战略/战术模式区别：** `5130`原始E8调用候选只有`4E6C/4EEB/4EFB`，各自前导明确`4E6A B001`（野战）或`4EE9 B000 / 4EF9 B000`（攻城）；`52D7`调用只有5146/5150。这些正常战略速算入口**没有AL2**，不能因52D7支持索引+10就说所有水路速算直接取水战专长。水战专长仍经55A6派生1F影响主守军和去向，且战术9C13确可由D34B=2直接读取。全程序间接call未知边界同武将§4，不将直接调用搜索升级为绝对不可达证明。

### 武将 3.6 职责、预算、对白的写回边界

- +17=1编成：`6F3F c685574201`；+17=2内政任命`6AD8 c6471702`；+17=3外交任命`6BB3 c6471703`；+17=4被俘`29F0 c6471704`。
- 两种手动解任都清预算与身份：`6B67/6B6B`、`6C42/6C46`。**两个任命函数没有清预算**；据点陷落`4D7E`、驻在势力灭亡`5091`只清身份；军团正常解散`467A`、回归`2A8E`也只清身份。
- UI状态：`7771 mov al,[si+17]; 7774 test al; 7778 test byte[si],40; 777D mov al,5`，索引CS:75A4的6字节文字槽。原字符串为 `－－－/軍團長/內政官/外交官/俘虜　/君主`。SI从772B武将候选指针装入，7739压栈，7769恢复；**不能把7778标为势力财政bit6**。
- +1A批准写回：`3ADF mov ax,[bp+8]; 3AE2 shl ax,1; 3AE4 mov [si+1A],ah`，现行输入上限30000下为`floor(grant/128)`，随后扣款。`3AD9 cmp option,2; 3ADD je 3AF8`说明拒绝跳过写回/扣款，不能笼统说任何拒绝都主动清旧预算。
- +1E个性索引：`075B`对CX>=196按`196+(CX-196)*8+AH`展开，没有`AH&7`。预算等池`3C99`则读full+1E，>=3先减3再加selector。君主被俘且未永久退场会`1E +=3`并清attr40；这是内容角色态关联，不是随意初始化后永久不变。

## 武将 5. 给未来自定义内容的约束（仅研究结论）

- 全32B必须无损保留，字段“未知”和“派生”与“可编辑内容”分层；不要手改生成资产或给未知offset发明名称。

### 据点 4.4 `43D3`线性别名与`441B`真城字段

`2662`抵达节点后先`266E CALL 28F4`，该函数令`DI=BX*4`，BX为节点`idx*8`，所以DI遗留`idx*32`。`4325`只把目标城指针放AX，不给DI加0840。状态1处理器`43AF..43E8`仍使用遗留DI：

```text

43C9 TEST BYTE [BX],40h  // 真目标城attr
43CE CMP BYTE [BX],80h
43D3 CMP BYTE [DI+18h],2 // 未加0840的状态段线性别名
```

若当前/目标均为第k个据点节点，别名精确为：

- `k=0..47`：势力`floor(k/2)`；k偶数读该势力`+18`，k奇数读`+38`。
- `k=48..65`：读外交区`0600..083F`内的相应byte。
- `k=66..191`：读**city[k-66].+18**，不是city[k]。

状态2处理器则`440F 8BF8 MOV DI,AX`，所以`441B CMP BYTE [DI+18],1`及`4455/4462 DEC BYTE [DI+18]`均是真目标城缓存。

状态1：在路上→0；总兵<=300→10；真目标城bit6→0；否则城bit7清零或上述别名>2时才RNG写1..8动作延时并转2；别名<=2才接着检查低兵首都重编。状态2：bit6或(bit7且真缓存<=1)→1；否则消费势力一次性城目标或按attr进入11，并相应减真缓存。由此自定义**较早城槽内容/势力记录甚至外交字节**可能经原始bug影响另一军团决策，不可把位移bug悄悄修正后还宣称DOS一致。

### 据点 5.3 邻接与边界不应混为一个字段

## 据点 8. 编辑器基础可采用与不可采用的约束

以下是证据导出的数据完整性建议，不是本轮实施的产品决定：

1. 基础字段分为名称/坐标/类型/景观/生产力上限/城兵上限等内容，与当前生产力/上昇率/防災/城兵/owner/governor等章节状态，再与14/15/17/18、attr高位、1A/1B等运行态区分；**分类不授权删除运行态字节**。
2. **自定义修改owner或邻接后，必须同步或重建所有受影响据点的attr低4位与+1B**，否则数据不一致；不能依赖原版新局自动修复。原版载入沿用这两项，后续城破仅增量维护当前双向边。修改邻接应先校验紧凑、互反与拓扑一致性，再重建边界；仅对新邻居调用88CC不能保证清掉已移除旧邻边。完整原版导入未改owner/邻接时应原样保留；不要因此同步city+1A旧所属。此处规定未来内容的完整性条件，不实施编译器/编辑器，也不新增产品自动修复策略。
3. 对从零创建的章节，城兵当前<=byte上限、生产力当前<=word上限是正常初始化约束；type4零城兵仅为官方样本约束，不冒称代码强制。

```python
for n in range(2, 128):
    states = {(n - 1, 1)}  # (DH, DL)，进入第一个匹配槽之前

        for dh, dl in states:
            assert dl == 1

            if dh:

print('PASS: cache=N, DL=1时所有分支在N个匹配槽内结束')
```
