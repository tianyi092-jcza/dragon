# 新建游戏与游戏资源（Web 产品决定）

> **全部内容是用户 2026-10-31 明确的 Web 产品决定，不是原版机制。** 原版 DOS《卧龙传》只有 20 个固定剧本、玩家只能选其一开局，没有"新建空白游戏"，也没有"资源库登记"概念。以下决定按 `E:/Dragon/AGENTS.md` 要求标注来源与范围，不得写成原版一致。

## 1. 决定摘要

| 项 | 决定 | 取代 |
| --- | --- | --- |
| 菜单「建立遊戲／完整副本」 | 改名 **「新建遊戲」**，单一入口，不分角色 | 原双流（作者中立模板／管理员完整副本） |
| 新建行为 | 填名称＋简介 → 点一次「確認新建」→ 直接产出**原游戏完整 20 章副本**，结束 | 原「預約→執行→查詢→取消」四步 |
| 名称长度 | 8 码点（不变） | — |
| 简介长度 | **100 码点** | 原 20 码点 |
| 配额 | 每用户最多 **3** 个游戏 | 无限制 |
| 中立空壳模板 | **废弃** | `FIXED_TEMPLATE_PROFILE` 作者路径 |
| 菜单「固定庫登記」 | 改名 **「遊戲資源」**，去掉登记语义，所有用户可看 | 管理员专属运维登记页 |
| 游戏资源内容 | 400 个内置只读素材，分类浏览；音频可试听 | 「建立本次驗證登記請求」等四按钮 |
| 库登记动作 | 服务启动时**自动完成**，用户不可见 | 操作员手动点登记 |

## 2. 新建游戏

### 2.1 交互

单一表单：

```text
遊戲名稱  [____]   （≤8 码点）
簡介      [____]   （≤100 码点，可空）
        [ 確認新建 ]
```

点击后一次性完成：创建 + 执行完整复制。成功后展示新 gameId，并出现在「自己的草稿」。

### 2.2 底部保留的既有能力

「自己的草稿」列表保留：跳转草稿编辑（測試運行）、跳转删除追踪。这两项是既有已验收能力，不在本次精简范围内。

### 2.3 技术上保留幂等

界面只给一个按钮，但内部仍是 `create` → `run` 两次请求，携带同一幂等键：

- 网络丢包后用户再点，不会建出第二个游戏；
- 若 `create` 成功但 `run` 失败，同一按钮变为「**確認新建（續）**」，用原键继续，不新建。

这是防止重复扣配额与重复写对象的最低要求，不是给用户的额外步骤。

### 2.4 配额

新增环境变量 `EDITOR_GAME_LIMIT`（默认 3）。在 `AdminFullCopy.reserve` 事务内校验：该 owner 现有 `content_games` 行数 ≥ 限额时 `fail(429, 'GAME_QUOTA_EXCEEDED')`。该检查与插入同事务，避免并发穿透。

## 3. 游戏资源

### 3.1 定位

**只读查询页**，展示系统内置的 400 个共享素材。没有"登记""验证""重放""放弃关联"等运维语义。

### 3.2 分类（按实测数据）

| 分类 | 内容 | 数量 |
| --- | --- | --- |
| 頭像 | `kao/*.png` | 150 |
| 圖像／圖塊 | `grf/*.png` | 226 |
| 音樂 | `grf/*.flac` | 11 |
| 音效 | `grf/*.wav` | 2 |
| 字體 | `font/*.woff2` | 1 |
| 其他 | 根目录 json／bin 配置数据 | 7 |

### 3.3 能力

- 分类切换 + 文本筛选
- 图像类：缩略图预览
- 音频类（13 个）：点击试听（`<audio controls>`）
- 不标注"当前游戏是否使用"，保持纯资源浏览

### 3.4 与既有「素材庫」页的区别（不得合并）

| 页 | 作用 | 数据范围 |
| --- | --- | --- |
| **素材庫**（`library-editor`，保留不动） | 核验"我这个已保存修订用到了哪些素材"，可核验下载 | 绑定某个 draftRevision |
| **遊戲資源**（`catalog-editor`，本次改造） | 浏览系统内置全部 400 素材 | 全局，与草稿无关 |

### 3.5 自动登记

`vps/publication-main.mjs` 启动路径在 `startPublicationServer` 之后、监听之前，用已装配的 library 描述符调用与 `/api/admin/library/install` 相同的内部登记逻辑（`InstalledSourceCatalog.install` 需要一个 authenticated actor，故改为内部直调 `#verify` + INSERT，或复用 bootstrap 逻辑）。失败则启动失败（fail-closed），不静默降级。

## 4. 废弃中立模板的范围

- `FIXED_TEMPLATE_PROFILE` 不再用于新建；`authorCopies` 改用 `FIXED_COPY_PROFILE`。
- `POST /api/games` 保留路径（客户端契约不变），但内部走完整副本 profile。
- **历史数据不迁移、不删除**：已用模板建的草稿仍按各自 `copy_origins.profile_revision` 读取（既有代码已支持按行内 profile 判定），不批量重写、不静默重解释。
- `copyprofile.js` 里 `builtin-template` 的校验分支保留（历史草稿需要），只是不再产生新数据。

## 5. 验证要求

- 真实 HTTPS：新建游戏一次点击 → 20 章副本落库 → 草稿可读；
- 幂等：同键重放不建第二个；配额第 4 个返回 429；
- 游戏资源：分类计数与 `available-library.txt` 一致（150/226/11/2/1/7）；音频可播放；所有已登录用户可访问；
- 素材庫页行为完全不变（回归）；
- 不读真实 `SAVE.DAT`、不碰用户存档。

## 6. 明确不做

- 不做"当前游戏已使用哪些素材"的标注；
- 不做资源上传、替换、删除；
- 不解除发布／管理／删除维护门；
- 不改变 20 章副本的内容与规则。
