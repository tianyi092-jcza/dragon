# Web 扩展第二阶段：存档、地图资源与受限内容编辑

这是用户批准的 Web 工程扩展，不是新的 DOS 机制结论。保持原生 ES Modules + Canvas 2D、静态部署、单一规则/AI 内核；原规则容量、RNG、调度、道路搜索和快照字段不变。继承[第一阶段](web-refactor-phase1.md)的行为基准。

## 1. 多存档与存储职责

- 解除四档硬限制；档号是非负安全整数，不是 DOS 槽号。仍显示最初四个占位，填满后保存列表提供下一空档；保存窗口保持原样式与四行视口，用滚轮或右侧滚动条浏览。标题读档列表复用原滚动窗口，按稳定档号而非可见行号加载；空/不相容档仍三路禁用。
- `savecatalog.js`：身份、摘要与列表；`saverepository.js`：隔离所有权，`list/get/put/add`；`indexeddbsavebackend.js`：原 `wolong-web` v1 的 `saves` store，正文键 `record:<id>`、摘要键 `catalog-v2`。一次单档保存只写该档和摘要目录，在同一个 readwrite 事务内完成；request 成功后 abort 仍是失败。
- 第一次写入新结构时在同一事务内复制旧 `slots` bundle，不删除旧键；后续以新目录为准。不是要求保留所有旧格式，更不放行不兼容规则快照。未访问或清理真实用户档案。
- `add` 在事务内分配新档号，供新档和导入使用，并发调用不覆盖彼此。App 保留保存串行队列和守卫，提交成功后才改内存索引；不克隆/重写其它档的全部规则 RAM。
- 无服务器数据库或联网同步；后端接口允许后续替换。数量仍受浏览器配额、可用内存及安全整数域约束，不能宣传物理无限容量。配额失败沿事务失败路径报告并保留旧档。
- **尚保留的成本**：游戏标题为维持同步的完整准入与禁用判断，启动仍读取全部快照；管理页只读摘要，按需取单档。大规模档库的游戏端懒加载需另改异步准入交互，不能声称本阶段已完全解决启动内存增长。摘要目录也是单条小索引，并非分页数据库。

## 2. 独立存档管理页

静态服务器下打开 `saves.html`（例如 `http://localhost:8321/saves.html`），不在原军师/系统菜单增加工具项。

- 只展示单档摘要，逐档导出 JSON；导入总是另存新档，不覆盖原档、不启动游戏、不热换场景。
- 文件格式 `wolong-web-save / version 1`，带 Web 规则实现版本。限制 64 MiB、拒绝危险对象键/非有限数/过深嵌套；核对 RNG、内容与世界身份，再复用生产 `admitSavedScenario` 和完整 detached `prepareScenario`。导出也校验实际 JSON 往返后的数据。
- 不接收 DOS `SAVE.DAT`；不猜补未知字段、不修复坏档。内容修订不相容时拒绝。它是便携备份格式，不是签名、防篡改或服务器认证协议。
- 游戏已开时，请先保存进度、返回标题，再刷新以看到管理页导入的新档。正常游戏内读取仍先返回标题。

## 3. 地图图集与分块绘制

- 编译器在保留四季整图参考产物的同时，生成四张 `256×256` 的 `map_atlas_<season>.png`。图集按原 tile index 排列；布局仍读 `mmap_map.bin` 的独立副本，不读写规则 terrainMemory。
- 默认世界季节资源改为小图集 + 布局；整数 DPR 下，只生成可见的 512px 分块，含一圈图块边缘以避免接缝，LRU 最多 32 块，RGBA 理论上限约 37 MiB（不含 Canvas/驱动开销），而整季图约 96 MiB。没有性能基准证明具体 FPS 提升。
- **像素优先的例外**：非整数 DPR（例如系统缩放 125%）的浏览器近邻采样对纹理范围敏感。此时从图集生成一张当前季节整图缓冲，保持原采样；切回整数 DPR 后丢弃该缓冲。不能声称所有显示环境都享有同一内存降幅，也没有保留四季完整缓冲的全局缓存。
- 仍是现行 1:1 地图，不新增缩放功能；`MapView.zoomAt()` 原本就锁定 scale=1。实验性 1.5 倍缩放未达到逐像素一致，不纳入支持域。旧整图 loader 供显式不含 `seasonAtlases` 的世界定义回退使用。
- 世界所有权、晚到图像保护、相机、城市/军团覆盖、输入、计时和 AI 不变。资源 URL 缓存仍按 URL；重新部署内容需刷新页面，当前局不热换地图。

## 4. 现容量内容编辑器（受限首版）

打开 `editor.html`。编辑页面在副本上操作，支持撤销、导出 SHA256 绑定源文件的补丁；不写 IndexedDB，不直接修改内置内容或当前局。

已开放：
- 20章内现有据点的六项具名内容字段：`max_prod/prod/growth/defence/troops/troops_cap`，使用现有 word/byte 域，不新造公式。
- 原 256 图块的地图单格绘制与预览。地形索引也参与规则，所以这是内容改编，不是纯美术覆盖；贴道路图片不产生道路。

明确未开放：增加/删除/移动据点、道路重连/点列/成本表、任意地图尺寸、武将/势力容量、未知兼容字节、AI/成本公式。编辑器不是任意地图生成器；改动可能因道路边界语义不一致而被拒绝，甚至合法格式的新内容仍可能触及已有规则未覆盖域。

补丁落地示例（仓库根；输出目录必须尚不存在且位于源目录之外）：

```bash
python -B tools/apply_content_patch.py --patch /path/to/wolong-content-patch.json --output /path/to/new-source --revision my-content-2
python -B tools/compile_content.py --source /path/to/new-source --output /path/to/new-generated
```

应用工具只允许原目录内章文件和 `world/layout.json`，核对基准 hash、容量、字段白名单和兼容字节，复制到临时目录后运行现有完整内容校验，通过后才发布**新源目录**；不覆盖原源。必须指定新的内容 revision，避免改图/改章冒充原内容身份。编译输出仍只是数据/地图产物，需要与匹配源码目录、其余静态产品资源一起人工部署；不自动发布、不提供当前局热加载或任意资源上传接口。此工具不把格式校验当作完整战役兼容认证。

## 5. 验证与边界

新增/扩展专项：`verify_save_repository.mjs`、`verify_local_saves.mjs`、`verify_content_editor.py`、`verify_expansion_browser.mjs`。覆盖原子多档、并发分配、不覆盖导入、实际 App 保存守卫、JSON/RNG 往返、标题准入、滚动命中、管理/编辑页、四季×三种 DPR×四个视口的48组逐像素对照。

固定20章状态/资源与槽/RNG基准继续不变。完整回归数字、既有失败和诊断覆盖限制只记录在 [checkpoint journal](checkpoint-journal.md)。超过192据点、地址/ID解耦、扩大固定槽和新的调度策略仍属于第三阶段，不借此绕过原未覆盖输入的 fail-closed 边界。
