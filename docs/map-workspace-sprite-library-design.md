## 1. 目标与边界

**海域自动铺底、原始精灵分类成库、拖放吸附拼图、四季共享布局；尽可能让出地图空间。**

实施范围：
- 全编辑器共用左侧导航折叠；不改变模块权限、当前游戏选择和未保存离开流程。
- 管理员“基礎地圖”与游戏“地图”复用的工具栏、画布、图层/属性区、素材相册。
- 以登记原图块和四季图集建立经过审阅、可追溯的精炼组件库，不再把地图切片清单当成默认创作素材库。
- 已支持域内的拖放、格吸附、海域背景表现及显式海域基底写入；仍走共同编辑/编译核心。

不包括：任意拓扑、新道路/节点生成、移城、扩容、新规则公式、自动生成完整可玩空白地图、自动迁移真实模板/旧copy、重开Trial、图片上传或引入新UI/图标依赖。当前固定384×256、16px格、192原生槽门不变。普通新建仍复制当前系统模板，不被悄悄改为空白海图。

## 2. 基线事实与本次纠偏

| 基线事实 | 本次处理 |
| --- | --- |
| 一份地图布局，`mapatlas.js`只切四季图集，默认春季 | 改为四个直接切换的预览TAB，不建立四份地图 |
| 原子定义256项，转换定义2101项，初始共2357项 | 数量不是“原版2357种独立精灵”的证据 |
| `system_base_map_pieces.mjs`按视觉区间/四邻接及16×16格区块提取片段，再按类别和相对tile配方哈希去重 | 仍可用于保真编辑旧图，但不作为新精炼素材库的主要提取算法 |
| 截图出现2358项 | 未读取该用户实际模板，不能确定多出一项的来源 |
| 缩略图将16px图块撑大，表格同时显示内部名称和放置按钮 | 改为原像素相册，名称/ID不常驻 |
| 基底/装饰/道路/据点是数据层，不是美术类别 | 图层保留；素材按视觉用途另分类 |
| 地图下层未知有显式unknown记录 | 不用海域背景掩盖未知，也不凭空补海水规则 |

已解码原图块不等于已确认全部多格自然对象边界。原始图块排列、像素、规则byte及现有明确配方可复核；类别、推荐组合和拼接用法标为Web创作定义。不得将视觉分类写成野战/通行分类。原证入口见[准入原证§2](re-notes-editor-map-admission.md#2-分层地图可以分开创作但不能分裂规则权威)和[数据格式SKILL](../../.agents/skills/re-data-formats/SKILL.md)。

## 3. 整体布局

```text
┌左导航────┬────────────────────主工作区─────────────────────────────┐
│图标+文字 │基础地图/游戏摘要 [重读] [保存] [撤销]   [春][夏][秋][冬] [全图][+][−]│
│可折叠    ├────────────────────┬─────────┬─────────────────────────┤
│          │                    │紧凑图层 │分类TAB                   │
│          │      地图画布       │眼睛/锁  │原像素素材相册             │
│          │                    │按需属性 │分页 / jumper             │
│授权/折叠 │                    │         │                         │
└──────────┴────────────────────┴─────────┴─────────────────────────┘
```

- 宽屏工具栏一行：左侧上下文/保存操作，右侧季节及视图工具；短状态不另占长期固定一行，长错误按需出现且可滚动。
- 取消中间常驻小地图。仅撤工作台DOM/Canvas订阅，**不删除游戏小地图、自动小地图编译资产或水域显示标志**。水域开关仍可在按需管理视图编辑并在发布产物验收。
- 布局宽度是骨架约束，不是控件皮肤：建议导航展开约200px、折叠采用ElMenu默认宽度；图层/属性约160–190px、素材约260–320px，地图`minmax(0,1fr)`吸收余宽，具体在1600×1000/900×700验证后收敛。
- 窄屏使用可切换的侧工具面板/抽屉，不同时保留两条挤压地图的宽侧栏；不改变全站其它页面布局。画布外整页不横滚/竖滚，工具区内部滚动。
- 长哈希不作为属性标题；常驻显示可读用途、格数、坐标。调试ID仅按需查看。
- 保持Element Plus默认组件、主题、size、繁体locale；不重定义`--el-*`或统一缩控件。用户允许说明12px或删除，本设计选择删除冗余常驻说明，必要文字使用默认提示样式，避免新字阶覆盖。

## 4. 全站导航折叠

采用`ElMenu`的`collapse`模式，不用手风琴`ElCollapse`代替垂直导航。保留原分组、角色过滤、激活项与导航动作协议。

- 每模块有语义稳定的图标；折叠只显示图标并提供Tooltip/可访问名称，不能依赖图标颜色识别。
- 折叠开关固定底部，展开/折叠使用不同方向图标。不安装新图标包；优先已有可用资源，否则自有简洁SVG配ElIcon，许可清晰。
- 删除“草稿與正式版本分離／遊戲規則共用同一引擎”。保留现有第三方授权链接，展开显示短文字，折叠显示信息图标；许可文件与访问路径不删除。
- 折叠仅工作区状态，不写模板/copy，不触发保存/丢弃确认。刷新默认展开；本期不新增跨用户持久偏好。
- 地图容器用ResizeObserver适配；保留缩放和原视口中心，边缘按有效范围夹紧，不因折叠重读地图、丢选择或重置全图。
- 角色、游戏切换及dirty拒绝维持既有共同context；全站模块都要核折叠后仍可达，不只验证地图。

## 5. 季节、网格与图层

### 5.1 四季预览

使用一组默认Element Plus Tabs，标签“春／夏／秋／冬”，放在工具栏右侧；不是下拉框，也不是四套地图子页面。只有一个画布/私有源实例，禁止为四个Tab各挂一份编辑器。

季节选中只切换同编号图集，地图实例、顺序、规则byte、地理和待保存命令不变。相册及拖放幽灵预览同步季节。异步加载保留SHA/长度/尺寸门和代际丢弃；图集未就绪不得用旧季节图冒充新季节。反复切季不增加dirty或重复写请求。

### 5.2 单元网格

新增工作区“网格”开关，默认开启；不是保存数据。建议屏幕单格≥16px时显示细线，缩小时隐藏密集细线；颜色用高低对比双线或浅深组合保证海域/山地均可见，不改变原图像素。

网格、选中轮廓、拖放轮廓必须视觉区分；线宽保持屏幕像素，不随世界缩放变粗。DPR、滚轮缩放、导航折叠后与真实格边界一致。网格开关不能改变导出、SHA、RNG或小地图。

### 5.3 四层紧凑控制

保留基底/装饰/道路/据点，每行“名称＋眼睛按钮＋锁按钮”，无宽“显示/锁定”文字列；状态切换有形状区别、Tooltip、aria-pressed和键盘焦点。图层锁仍限制命令，不只是按钮变灰。道路/据点当前只读约束在选中时说明，不摆常驻大段提示。

眼睛/锁仅编辑工作区；隐藏层仍保留数据。海域属于基底显示与规则合同，不新增第五套可独立推进的地形权威。

## 6. 精灵素材库（本阶段核心）

### 6.1 三层模型与默认展示

1. **原子库**：已登记16×16图块及四季对应，作为可追溯基础；不删除未使用或外观相同的原byte身份。
2. **精炼组件库**：单块、直段、转角、端头、必要交汇、明确的多格组合；面向创作的默认相册。
3. **地图实例/历史片段**：具体坐标摆放、旧`web-piece-policy-1`片段和作者捕获物。历史片段不混入默认精炼库；原图仍可选中/拆分/编辑，作者素材另有“我的素材”入口。

不能用删除2101个定义的办法实现“去重”：现有实例仍引用它们。不能把整张山脉或随意截取的地图大块冒称基本精灵。

### 6.2 分类TAB

默认素材面板提供分类Tab：地面（陆地/草地/海岸）、山地、水系（河流/湖泊）、农田、墙体（长城/墙段/关隘外观）、道路/桥梁、城镇/据点外观。标签可水平滚动或按窄栏提供同组件导航，不退回把全部素材塞一个下拉列表。

海域通过背景工具管理，不放大量重复海水卡片。另有“我的素材”和“原始图块（高级）”；问题定位/水域管理是工具视图，不冒充素材类别。分类名称为Web目录标签，不改变四层及规则身份。

道路/据点类只开放已经受证的能力；未获拓扑准入的卡片可检视，但不得提供貌似成功的拖放。清楚注明“外观参考/当前不可新建”，不能把道路图块改成普通装饰绕过编译门。

### 6.3 全量盘点与提炼方法

实施时先产生可复核目录，而不是立即手写一个小样本列表就宣布全库完成：
- 核固定源revision/manifest/SHA、256原子槽及四季图集；为每槽记录原资源offset、原byte、四季图像摘要、使用情况、候选类别与置信度。
- 使用现有原图上下文辅助判读，但不从四邻接/颜色自动推导规则或自然对象身份。
- 对每类整理直段/转角/端头等实际存在的配方；多格组合列完整有序相对坐标、原byte、锚点、footprint、地理mask、受信recipe、源引用。
- 全部256槽都要落入“精炼目录引用／底板使用／只读参考／高级保留／待辨识”之一，数量可汇总、无静默遗漏；未知不能塞进已确认正式类别。
- 山地、河流、墙段、农田先各做代表样板及拼接示例，再扩充全目录。只在确实存在实质歧义/审美验收需要时请用户判断，不重复询问已明确的UI决定；不以用户视觉认可代替规则原证。
- 自动化工具只生成新隔离目录，报告源摘要、算法版本、组件数、别名/重复组及未确认项；不反写原资源或生效模板。

### 6.4 去重标准

同时维护两个概念：
- **严格组件身份**：相对位置规范化后，比较footprint/anchor/所有variants的原byte配方、recipe、地理mask/水类别和相关语义约束。无序对象键规范化、格序确定；不因实例绝对坐标生成新素材。
- **展示相似组**：四季像素相同但规则不同的内容可相邻呈现或在卡片中选变体，不能丢掉实际身份。只比春季PNG、名字或单季颜色都不够。

不自动旋转/镜像图像来冒充已有图块；方向必须有受证的显式配方。字节相同但锚点/用途不相同，先记录区别，不能为了卡片更少强合并。多类别复用同一素材引用，不复制配方。验收提交去重前后计数和重复组样本，而非承诺一个未经核实的目标数量。

### 6.5 持久化与服务边界

优先以**程序随附、版本化、只读的目录索引**组织已有受信定义；索引不是另一份live地图。推荐字段职责：catalogRevision、稳定目录itemId、分类/标签、definitionRef或显式受信recipe引用、锚点/占格、四季来源摘要、支持状态、溯源。具体JSON落位在实施S1按现有schema确定，不直接给严格template root塞未经验证的新字段。

- UI仅接目录DTO/当前页缩略图引用；模板、copy、位图、完整源留框架外。
- 放置新精炼配方时，在所属模板/游戏内物化所需定义和实例；相同完整配方复用既有定义。保存后同样内容可独立编译，不依赖后来变化的“最新目录”。
- 服务器只接受登记itemId/配方引用及合法位置，或现有受限capture/placement命令；不能接受客户端任意recipe、文件路径或预算。
- 若现有14命令不能表达目录物化，应新增最小明确命令，在共同编辑核心、服务allowlist、身份ledger、预览、票据失效和测试中同步，不能只在客户端Object.assign偷改定义。目录物化与放置必须原子，无半定义/半实例残留。
- 保留旧冻结profile、38角色manifest和1024原门；新目录的配方预算须显式有界并有满额负控，不简单将所有定义算作转换豁免。当前作者素材预算及256格上限未获扩大。
- 目录代码更新与内容发布分开：普通保存/发布不触发构建/部署。系统模板/游戏仍独立、复制只取单快照；删游戏不删共享目录/资源。

### 6.6 原像素相册

- 以CSS像素1:1展示图块（16×16素材不拉大成64×64）；DPR只增加画布后备像素，不改变视觉尺寸，关闭平滑插值。
- 用留白和边界形成可点击卡片，卡片命中面积不必等于小图尺寸；图片与交互控件尺寸分开。多格组件按实际尺寸排布，过宽者裁切并提供完整原像素预览，不自动缩放成无法辨认的一团。
- 常驻不显示名字/哈希/放置按钮；悬停和焦点提示用途、格数、能力限制。内部ID仅调试详情。选中边框与键盘焦点清楚。
- 分类内分页25/50/100与jumper，默认25，仅挂当前页；相册网格取代表格，不影响其它模块表格规范。切页/切类/离开取消拖放，不修改内容。
- 拖放之外保留键盘可访问的“选素材→地图确认放置”操作，不要求用户只能使用鼠标拖拽。

## 7. 拖放与单元吸附

共用Pointer/坐标变换与现有stage命令，不引入拖拽库。

状态：idle→选择/拖动→有效或无效幽灵预览→松手一次提交，或取消→idle。

- Pointer移动只更新工作区预览，不写源、不反复stage。画布外松手、Esc、失去焦点/捕获、身份或游戏变化、切分类、图集失效均取消。
- 从DOM实际rect换算至画布CSS像素，再经screenToWorld到格坐标；素材锚点吸附整数格，预览位置与提交位置完全相同，处理非1缩放/DPR/折叠resize。
- 预览画完整footprint，空洞不冒充覆盖；显示锚点和占格。越界不裁切、不扩图；锁层/能力不支持明确拒绝，不留下命令/实例。
- 松手使用当前会话、当前目录项和当前支持门复核，最多产生一次原子编辑；取消不消耗持久实例身份。不在本期增加边缘自动滚动、批量铺刷或自动河流寻路。
- 不自动修复邻居图块、不旋转或生成未知连接变体。初期由用户选已整理的直段/弯角拼接；“吸附”仅对齐格，不等于规则自动连通。
- 服务拒绝保留已存在的本地输入；未知写结果继续锁定防重放。模板完整验证与游戏copy草稿保存/发布全量门维持区别。

## 8. 海域背景：显示简单，规则不能缺席

### 8.1 表现与数据分开

海域不要求用户逐块拖放，采用源图集中经核定的可平铺纹理/周期配方，由基底渲染自动生成。四季使用同源编号对应外观，不新造颜色；默认不制造大量海水实例。

但Canvas背景不是通行/野战数据：编译时每格仍须有明确原byte和地理贡献。优先复用现有base.terrainRef/base.geography，不为视觉便利另建一套权威地形。

### 8.2 既有模板安全策略

- 本期不得自动清空当前模板、删除旧海水实例、给全部unknown补海或将普通新建变为纯海图。
- 已有海域可以做经逐像素验证等价的批量绘制优化；不同纹理、岸线和地理贡献不合并。旧实例/组/摘要保持不变，除非作者执行明确编辑。
- 可在基底工具提供“海域填充”：作者显式选择格/范围，使用登记海域配方一次写base并可撤销。大范围若超请求预算不得分批部分成功，需有界区域命令及服务同事务支持后再开放。
- 尚未知的覆盖下层仍unknown；露出时保留警示/诊断，不能画出普通海面让人误以为规则已补全。
- 不提供绕过192槽/道路门的“生成可玩空白海图”按钮。后续完整空白图初始化需独立支持域方案，不是本轮背景平铺的隐含承诺。

### 8.3 必须解决的地理与拼接细节

现行composer中“非水装饰不擦除下层水域地理”。因此**不能将base.geography全设海，再只盖陆地图块**，否则小地图仍可能显示海洋。

实施应显式区分：不改变地理的普通覆盖物，以及作者使用地面/海域工具时对基底地理的明确写入。新地面组件需要修改base时，目录必须给出已确认的地理作用域，放置/基底写入同一可撤销命令；不得以显示类别/颜色推地理，也不得隐式改变原非水覆盖规则。删除装饰只移除装饰，不凭旧截图恢复先前基底；撤销才精确恢复本次编辑前数据。

许多原图块带有不透明地面/岸线，不是透明贴纸。背景不能自动消除方边；陆海/河岸交界要用原图块中实际存在的连接素材。纯海纹理若四季无法无缝重复，先使用已确认周期配方，不硬拉伸整图或随意造纹理。
