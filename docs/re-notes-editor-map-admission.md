## 2. 分层地图：可以分开创作，但不能分裂规则权威

### 2.1 原始输入能提供什么

**原数据实锤**：只读解包`Dragon/MMAP.MAP`得到98,304字节，SHA256为`740708c27a89db0a7f82865be623b5732099ec97aabf399e7dbde1450c87c861`，与当前`web/mmap_map.bin`逐字节相同；使用238种tile，原图中心码CD／D0／D3分别183／4／5格。`MMAP.MDL`32,768B，现有解码按256×128B四平面16×16图块读取。

**代码／源事实**：`world/layout.json`是256行×384列整数；tileset的256项都是`opaque:true`，只含id/index/rect/anchor/opaque，没有山脉／农田等多格组件的语义边界、下层历史或四层叠放记录。这证明现有编辑源没有这份资料，**不证明原资源其它位置永远不存在相关描述**。MDL像素是已经合成的图块，不可据一个合成像素唯一恢复被遮挡地形。

**工程处理**：M0必须建立组件清单与多格锚点／覆盖，未知底层明确标unknown。原子图块保真记录可以覆盖尚未拆组的部分，但不能据此宣称全部山脉／长城／水系已成为完整可用组件。删除副本覆盖物时由作者补底层；不得凭颜色造一块“原来就是草地”。

### 2.3 易主着色：迁移要补齐的具体接缝

原`8A1E`在规范平面上写中心：`u8(CB + 3*floor(u8(oldTile-CB)/3) + ownerVariant)`；ownerVariant为玩家0、其它1、中立2。C16低四位仅选择角块偏移：大都市0为(±2,±2)，关卡3为上下左右一格，其它分支为(±1,±1)；仅DE..F1角块按是否玩家选DE..E7或E8..F1。这里描述的是**归属着色，不是8A1E修改城市type**。原实际使用段／word地址算术，规范XY表示不能冒充任意边界／段别名已获支持。

本轮官方四章各192城的XY与原节点顺序完全相同。每章按上述位置检查，768个候选角块中750个位于DE..F1（750个独立格）；是原图数据分布，不是任意城型的绘制范围定律。

当前代码事实：

- `scenarioassembly.prepareScenario`绑定初始完整terrain；无显式terrain的恢复还有现行合成路径。注释明确89F0开局着色未全面执行，8A1E目前在捕获路径。不能把这段注释／回退当作已认证的新创作初始化或新格式缺字段恢复政策。
- `originalcitycapture.paint8A1E`确实写同一terrain；`scenarioterrainmemory`提供read/write/snapshot，但没有revision／脏格订阅。
- `worldresources.loadSeason→createChunkedTerrain`复制不可变初始layout，`MapView.draw`另叠cityIcon；当前这条底图链没有消费运行terrain角块写回。单独叠中心icon不证明四角已更新。

**工程方案**：原规则每一次成功地形写保持既有提交顺序；在权威层记录只读变更版本／脏格，显示适配器将其映射到组件动态变体，失效相关块及非整数DPR整图回退缓存。恢复／重新绑定时可由已保存terrain与初始terrain差分重建显示，不重跑易主规则／RNG。不能写回编译源、共享世界缓存或另存第二份规则地形。开局89F0差异列为M0显式核对项；若迁移接线触及，须独立取得初始化证据再改，不能把旧静态画面当唯一golden。

**仍未知**：所有作者自由叠放的规则组合、完整原组件归组、边缘城市地址域、所有动态写者的穷尽与显示返回链。上述局部原证足以确定接缝，不足以关闭G-MAP。

## 3. 新道路／城市／章节：需要分别处理的转换

### 3.1 原道路可保真；新道路不能复用失效的绑定

本轮按v2布局重新编码当前源道路，低32KiB SHA256为`c226fc8fd8567ffc23a927e09419797d9d94b06c1b4d67bbf9b73909981e7afc`，点流SHA256为`d443c417625cf0e1b8caed90e3958f41a5fbe769e18a75f74965a897afc7ffea`；与[道路§2.5／§3.6](re-notes-march-pathfinding.md)已记录的原指令构图证书相同。**本轮没有重跑该CPU证书**，只是重取输入并验证字节身份。

数据检查：192节点、254边、5526点；点flags分布44:254、04:254、00:4225、01:159、80:634。跨边共享点0、共享相邻线段0、不同边单位斜线X交叉0；所有相邻点的Chebyshev距离均1。检查只覆盖边内部点流，尚不等于组件footprint、节点中心到端口连接区或新编辑器整个交叉判定已经验收。

`E717`四方向槽保持顺序；城市C1C..1F却是紧凑邻居索引，两者不能逐下标当成同一数组。`E7AE`写AH为byte成本；`E81C`特殊首点不INC AH，普通首点会INC。原254边恰好都是特殊首点，故成本N−1；任意新路不能无条件套这个样本公式。边点增删会改变后续点地址，须重编整个相关原生图及身份，旧对局仍固定旧版，不能热换点流。

另有两个**原指令局部实锤**，说明新图不能只检查几何：`E4AC MOV byte CS:[E47E],C0`固定构图节点轮数，`E770..E77A`每轮DEC该byte，不按实际扫描得到的节点数调整；`E899..E90A`前七邻方向检查E961返回CF，而最后东南`E912 CALL E961`之后直接`E915 INC CX / E916 INC DL / E918 POP DI / E919..E91E`写点，没有同样的CF拒绝分支。后者只证明该窗口的真实控制流；无邻居／坏seed时的完整后续行为仍未知，不能替原程序添加“找不到就正常无路”返回。

**构图待验证链**：作者明确几何／水陆种类→已证tile／seed recipe→原构图次序和flags／成本→互反四槽及地址检查→491B队列／耗尽／word累计费用→2708、2831、2880、野战五点分类→结果写回及保存。原图的队列条件证明不覆盖任意新图；几何没有X/T交叉，也不能证明不存在回路、不可达或搜索工作区风险。

旧`pathfinder.js`尚保留水格代价3、过渡加40、按地名坐标设关卡及A*函数。这些不是本方案的新路编译规则，也不能拿来填G-ROAD；当前原生路径与其工具／兼容消费者必须分别追踪。roadCost／roadOffset的取数接缝仍要审，但不得把roadCost像素值当edge+4的搜索成本。

### 3.2 城市编号同时是规则地址和战场选择

**实锤**：`27B8 CMP BX,0600`后以node×4寻城市0840表，`4AF3..4B03`由城市指针计算D34；`CAEB..CB43`以D34选择目录并读取`0x200+directory*0x1000`战场。当前`createSiegeProjection`同样按city.idx取图。城市数量／位置排序改变不是单纯改一个ID或图标。

工程拆分：

1. **不改变原槽的迁移／数值与图片编辑**：保留稳定cityId→runtimeSlot→battle目录绑定，并核原坐标／组件recipe；换外观不擅改战场。
2. **移动城市**：即使仍192城，也可能改变原E4CE扫描编号。必须同时重建道路及明确槽分配，并映射所有章节首都、目标、太守关联、邻居、边界位和战场关联；不能简单排序源城市数组。若选择不依原扫描号输出，须证明重编号后的共同编译合同等价，不能称原构图自然支持。
3. **增删节点数量**：当前profile没有“删城市后留个假中立城即可”的证据；用填充城、别名节点或将193号塞进表后空隙都不成立。未完成变槽适配前只能创作草稿，不能放行运行。
4. **新增城市战场**：没有可凭城图自动推导的战术地图。现有192个城市目录之后C0..D5已用于野战；第193个城市不会自然拥有第193张攻城图。必须解决目录寻址及资源完整性，不能复用任意野战图兜底；完整战术关联系统仍属G-SLOTS。

原`8CAE`批量载入固定状态表；`89F0`重着色并处理军团占格，**不会帮作者重算F18/F23或全部边界缓存**。本轮官方四章统计（0基章节号、0基势力号）：

`1AF8..1B25`复核：所选玩家军师非7F才DEC F18，随后清所选武将attr并写CFD/CFF；不是每势力军师都预扣一次。现Web已接普通军师这条fresh处理，编译期不能再次扣数。自定义Web化身的既定差异保持。

**当前源的具体陷阱**：`source_chapter`中的`connections`只保存attr位已置的异属邻居；未置位邻居仍留在raw，不是完整拓扑。`compile_chapter`依据connections写低位，却没有据新owner重建全邻接／C1B；F18又由旧显示n_generals加advisor_count恢复。因此它能服务既有受限补丁／导入保真，不能直接作为任意新路或章节归属编辑的编译器。新的作者源必须分别表示完整有序邻接（派生自确认拓扑）与异属状态，不能将同一connections字段继续混用。

**可以先闭合的字段组**：在固定槽／有证拓扑内，按[实体§9.4](re-notes-entity-fields.md)的前置状态合同同步C00低4、C1B、C1C..1F；保留高位及旧属记忆。F18/F23、人物未使用槽、投奔／官员／军师引用、隐藏势力、政策／外交矩阵和特殊G127另列初始化recipe，不把局部同步当整章完成。日期／全byte能力／signed24旧解析差异仍按既有G-INIT清单独立纠错，不因地图迁移顺手改规则。

| 保存与扩边原点 | 原native指针／节点地址随槽／布局，源bounds允许minX/minY | 左／上扩边会平移编译坐标，必须转换所有地图引用而非仅城市；正式旧局固定旧版，新版不假贴旧内容身份，不静默改档 |

扩容分三份证书而非一刀切：**画布／小地图显示域**、**同节点数下扩大地理域**、**改变节点及其它固定表容量**。前者的纯显示样本不证明后两者；后两者仍须在同一引擎中适配，不增加原图专用旁路或启用第二套AI。无法从当前证据给出“安全最大地图尺寸／新城市数”的承诺。

```python
from pathlib import Path
from collections import Counter, defaultdict
import json, sys
sys.path.insert(0, 'tools')
from decode_mmap import rle_decode

t = rle_decode(Path('../Dragon/MMAP.MAP').read_bytes())
g = json.loads(Path('web/content/builtin/world/roads.json').read_text())
s = Path('../原版/SINARIO.DAT').read_bytes()
assert len(t) == 384 * 256 and len(s) == 4 * 0x56c0
assert t == Path('web/mmap_map.bin').read_bytes()
locations, segments = defaultdict(set), defaultdict(set)
for e in g['edges']:
    ps = [(p['x'], p['y']) for p in e['points']]
    for p in ps:
        locations[p].add(e['id'])
    for a, b in zip(ps, ps[1:]):
        assert max(abs(a[0]-b[0]), abs(a[1]-b[1])) == 1
        segments[tuple(sorted((a, b)))].add(e['id'])
print('shared cells/segments', sum(len(v)>1 for v in locations.values()),
      sum(len(v)>1 for v in segments.values()))  # 0, 0
cross = 0
for (a, b), ids in segments.items():
    if abs(a[0]-b[0]) == abs(a[1]-b[1]) == 1:
        other = tuple(sorted(((a[0], b[1]), (b[0], a[1]))))
        if (a, b) < other and other in segments:
            cross += bool(ids != segments[other])
print('cross-edge diagonal X', cross)  # 0; 不含城市端口连线
for chapter in range(4):
    b = s[chapter*0x56c0:(chapter+1)*0x56c0]
    cs = [b[0x8c0+i*32:0x8e0+i*32] for i in range(192)]
    gs = [b[0x42c0+i*32:0x42e0+i*32] for i in range(127)]
    gc = Counter(x[0x1c] for x in gs if x[0] & 0x80)
    cc = Counter(x[1] for x in cs)
    assert all(b[0x80+f*64+0x18] == gc[f] for f in range(22))
    print(chapter, [(f, b[0x80+f*64+0x23], cc[f])
                   for f in range(22) if b[0x80+f*64+0x23] != cc[f]])
    for c in cs:
        mask = sum(1 << k for k, n in enumerate(c[0x1c:0x20])
                   if n != 255 and cs[n][1] != c[1])
        assert c[0] & 15 == mask and c[0x1b] == mask.bit_count()
```
