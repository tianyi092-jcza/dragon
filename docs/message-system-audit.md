# 原版消息系统覆盖审计

> 审计日期：2026-09-03。分类按**因果来源**，不是按说话人：玩家操作直接引发为主动；AI、月结、自动战斗及灾害引发为被动。结论分为实锤、实现偏差与待证，不把Web自拟HUD文案视作原版消息。
>
> 后续AI全链勘误：本页旧“48槽回归”仅能描述初始化48未经覆写的分支，不是通用等待期限；当前活动槽尾部可先清计数，详见[全链P01](re-notes-ai-chain.md)。这项机制差异尚未修复，历史FIFO测试不能代替槽续段认证。

## 1. 原版执行模型（实锤）

原版消息分两层：

1. **同步阻塞消息链**：战前报告、战后武将去向、失城/迁都/灭亡、玩家进言等在规则函数中调用 `0x8810`，返回前主流程不继续。
2. **四页战略事件轮**：256个4B槽、4页×64槽；新局/月结首槽等待7次势力调度，之后每10次消费一槽。type6/type7的20是事件槽偏移，不是天数；出队时才重读外交官并计算结果。

Web统一呈现契约：FIFO；显示期间 `clock.hold`；普通NPC/武将框3秒自动关闭或右键关闭；回调once；战术层及高优先级模态期间延后；状态必须遵循每个原调用的消息前/后写回边界，不能把所有修改统一延到整段最后（见§3.2）。外交费type5是强制交互例外：整段屏蔽右键，只允许左键选择、输入和推进；右键不能退出、暗中当作拒绝或改写已批准预算。

### 3.1 玩家失城消息的入口分流勘误

AI全链专项按固定KI原窗复核：`4ED7`判断参与方后进入玩家守方`4EF1`。无真实主守军的BX=4200h，`4EF7..4EFB`执行临时城防速算；`4EFE`先POP DI恢复城市参数，`4F02`测AL胜方，AL=0攻胜才`4F06→4F71`以CX=1Ah显示TALK26，AL非0不显示。`4F71`保存AX/DI，按攻将与城市压参，`4F7C→0CE7`警告、`4F81→8810`消息；返回后恢复寄存器，才回到`4B3A→4FC8`清临时军，`4B41→4CF3`提交易主。

若失陷的是玩家首都，`4DF0→6A3D`找到替代城后先写新首都并调用`4502`改相关命令，再在`4E42`显示TALK30，随后`4E48→5E60`。故这一路TALK26在易主和TALK30之前，不能调成30→26。

有真实守军时`4F0B`检查委任bit：置位走`4EE7→5130`直接返回，不经过上述26调用；未委任才`4F10→4F58`发TALK27后入战术。玩家攻方另走`4F2B..4F49`，不能复用无主守军玩家守方的失城通知。这里闭合的是入口分流与提交先后，不是完整`8810`设备/非局部终局退出认证。

**当前Web统一失城通知及旧FIFO golden不得继续充当原版机制依据，仍须同步修正生产/测试。** 上表和下文“已覆盖”是旧审计批次记录，不证明这一新发现的返回链已实现。哈希/全链范围见[专项总纲](re-notes-ai-chain.md)。

### 3.2 NPC停战的互俘消息并非整段提交终点

[P18原指令与独立复跑](re-notes-ai-diplomacy.md#12-互俘部分提交与和平边界)：3262的NPC同意路径先35ED转移钱，再逐127将恢复互俘，之后才45F8/4236/3669改目标、城oldOwner与关系。50D7若恢复玩家，会在该将所属/身份/旧属/将数已写回之后调用CDE与TALK37/个性0x199；此时后续和平尚未发生。

明确玩家提出方输入实际停在CDE入口：35000款项已转移、G40已恢复并加将数，关系仍00。不能整体回滚、提前写和平，或在消息返回后重复已完成付款/该将恢复。接收方玩家的另例更早停38C7，NPC计算结果不等于玩家已同意。两个停点均不是完整消息返回证明，不为此重启字体/显示专项。

因此“所有外交状态最后消息后一次性提交”的通用概括撤销；原入口、已完成子步骤与剩余续段分别一次执行。下方旧FIFO测试是表现/历史实现证据，不锁定这条新发现的原AI时序；正式实现与回归仍待同步。

### 3.3 type1重判与AI迁都通知之前的写回

[P19](re-notes-ai-diplomacy.md#14-p19type1生产后重新门控)的真实生产→31AE证明type1出队还会重查双方active/提出方F19；拒绝就不显示或提交。已战分支免显示但可再次减关系。因此上表“AI向玩家宣战FIFO”只适用于通过门控且原关系为和平的显示分支，不是每个已入队事件必播。

独立33EA→6A3D/4502在迁都外交官CDE入口停止时，F3及匹配军团的+20/+14/status已经提交；没有写+23返都命令。消息后不能重复迁都，也不能把未返回的显示证书叫整链通过。三处P19停点均保留真实入口，不用显示替身补返回；详细写集由外交笔记维护，不重启字体专项。

### 3.4 type2款项与宣战是独立提交阶段

[P22](re-notes-ai-diplomacy.md#29-先转款互俘再尝试宣战)的明示NPC输入真实执行35ED→3526：先给受邀R加钱、付款T减钱及互俘，之后3526仍可因R已有目标<18h拒战。该例钱已转20000、关系仍和平，不得为保持通用事务原子性回滚钱，或因已付款就跳过宣战门。另一例钱/一将已恢复后停CDE，3526尚未调用；续段不得重复前款。

原2BD9→2E33产生的type2受邀方为当时玩家；身份稳定时成功资格检查必到38E6。本批在其正文前停止，原CALL返回word324B已核；不是CDE/3902或玩家选择已执行。改玩家的NPC路径只证明该明确输入，不能伪装为合法中途换主或替代玩家返回。后续[P23](re-notes-ai-diplomacy.md#32-p23玩家选择不是87ff或算法结果)只闭合条件式静态链与40个局部片段，未把此暂停变成整体RET；不由下方FIFO测试或P22预计算AL认证。

### 3.5 玩家选择、金额方向与终局退出

type2的TALK376“提供资金”意为要求对方付给玩家；87FF不是输入，菜单及数字面板才生产row/金额。数字取消保留CF回菜单，正常返回后的3254则重新CMP AL2，不继承UI算术FLAGS。AL0可带旧DX但不转钱，AL1才付款；325B恢复原packet DX后才把攻击方交3526。

AL3是索取超过算法额的处罚结果，3C3D临时显示成拒绝不会丢原AL。信赖减30到0时1CB1改SS/SP，不能无条件恢复等待中的事件/世界续段。1D46存在军团bit4与对象相位写，并非纯绘制no-op；未证输入/命中平面及别名/真实栈存活，不用假消息返回掩盖缺口。

## 4. 本轮已修复的消息基础设施

- 新增 `tools/verify_strategic_message_fifo.mjs`，覆盖NPC→武将→NPC严格FIFO、3秒计时、右键与旧timer竞争的once、全链clock hold、模态门控恢复、reset期间异步头像旧消息不复活、入站外交最终关闭提交。
- 新增 `tools/verify_negotiation_message_commit.mjs`，验证玩家停战/请援使者的外交、目标与资金状态只在3秒结果框关闭后提交。
- 普通消息自动关闭timer绑定具体卡片，旧timer不能关闭后继消息。
- `_drainStrategicMessages()`增加场景UI generation守卫，返回标题/reset期间等待头像或TALK的旧消息不能复活并提交旧状态。
- `message.onClose`及入站外交commit使用`try/finally`收尾，回调异常不再永久卡住FIFO/clock hold。
- `onModalClosed()`现在主动恢复消息drain。
- 新增 `enqueueTalkMessage()`：有实锤TALK索引的规则事件统一通过TALK格式化后进入同一FIFO；已迁移TALK26..37、41、57、65..72。
- 已移除野战/攻城结果的自拟HUD摘要；战果对玩家的正式反馈只走原版TALK26..35/67及其个性对白，AI/委任速算无原版消息的路径保持静默。
- 复刻 `0x075B` 的选择器换算：`0x196 + (selector-0x196)*8 + general[+0x1E]`；通用段与个性段作为相邻FIFO条目，严格在第一段关闭后推进。
- 新增 `verify_extinction_message_fifo.mjs`，走真实`applyBattleResult→GameBar`，验证TALK68→0x1A6、TALK69→0x1A7、TALK34→0x19A、TALK36全链顺序、逐段3秒与持续clock hold。
- 复核`0x50B4`：仅调用`0x2BA8`清军团地图状态、`0x7028`注销军团并清武将`+0x17/+0x1C`，没有直接或间接TALK调用。`0x4D63`的TALK68条件仅为旧城非中立且`city[+0x19]!=FF`，函数内无玩家阵营判断。
- `verify_budget_message_ui.mjs`：type4/type5从真实GameBar出队；现经公开`GameBar.click()`覆盖type5选择、金额及结果阶段右键均无效，左键可完成“提示金额”与批准提交，预算不被二次清零且后继FIFO门控正确。旧测试只调用私有`_clickProposalAudience()`，曾漏过公开右键分发把已批准预算重写为0的缺陷。
- 新增 `verify_type10_message_fifo.mjs`：从真实战略事件槽出队type10，验证通用占位格式化和3秒clock-hold生命周期。
- 新增 `verify_advice_commit_boundary.mjs`：实测玩家迁都与请求君主出阵的最终对白关闭边界；修复两条成功路径此前在最终君主对白出现时即提交状态的问题，并让结果阶段右键等价于3秒完成回调且once。

## 5. 审计收尾结论

- 战略战果HUD旁路已清除；TALK26..38、41、51、56/57、63、65..72及宣战个性窗口均进入权威FIFO。
- 玩家迁都成功/失败、君主出阵成功/失败/已出阵TALK64，以及设置/战术模态期间被动消息等待均有边界测试。
- AI对AI攻灭势力的动态测试确认`0x4D63/0x5074`无玩家门控，仍产生TALK68/69同步链。
- 旧“扫描8810调用点即战略生产者已闭合”的结论撤销：TALK33后的2A43跳转已构成反例，且完整消息返回仍未认证；见[去向审计](re-notes-legion-fate.md)。0x19B/19C/19D/1A2/1A3等属于其它人事/内政菜单域，不冒充本次战略事件生产者。
- Web即时反馈仅保留存档结果、无效操作和开发中的非规则提示；不再承担原版战略规则消息。
