### 时钟层级（KI.EXE:0x1D8E 主循环）

```
[CS:0xCF2] 子刻度   0..7      (cmp ,8)
[CS:0xCF3] "日"计数 0..0x17   (cmp ,0x17=23)   ← 待动态验证语义
[CS:0_CF4] 月       1..12     (cmp ,12)
[CS:0_CF6] 年(word) 上限~1000 (cmp ,0x3E8)
```

- 每子刻度→日变化：call 0x9377（日处理）+ call 0x3E11（势力轮询）
- 换月：查每月天数表 @0x98AC=[31,28,31,30,31,30,31,31,30,31,30,31]，call 0x5358 季节画面切换
- 每季首日（3/6/9/12月）：0x9377 内做季度视觉更新（调色板/背景图选择表 @0x265F）

### 势力轮询调度器（0x3E11）

- 每 tick 处理 1 个势力，游标 [0xD1C]，记录 64B，共 22 个（si 到 0x580 回绕）
- 势力记录字段：+0 属性(bit7=活跃, and 0xBF 清 bit6)；+4/+6/+8 三字求均值 /8 → call 0x5673；+0x19 条件置 FF；+0x21 word vs [+0x23]*16 比较
- 状态段：[0xD52] ← SINARIO.DAT 全量 0x56C0 原样驻留；文件头 0x3B 字节另存于 CS:0xCF0（时钟区）

| --- | --- | --- |
| CS:0xCF2 | 子刻度 | 0..7 (满8进位) |

## AI 调度器逆向 (0x3E11 链)

### 调用关系

- 主循环(0x1D8E区) 每刻度 call 0x3E11 (唯一调用点 0x1E04=7660d)
- 0x3EFD 由 0x1D13(7443d) 调用 —— 主循环另一分支

### 0x3E11 势力调度器结构

```
call 0x31AE                     ; 作用未明(待查)
si = CS:[0xD1C]                 ; 势力游标
ds = CS:[0xD52]                 ; 游戏状态段
if byte[si] >= 0x80:            ; 仅处理活跃势力(bit7)
    byte[si] &= ~0x40           ; 清bit6
    ax = byte[si+0x23]*8 + 24
    if ax >= word[si+0x21]:
        byte[si+0x19] = 0xFF    ; 疑似势力灭亡标记
        if ax/2 >= word[si+0x21]:
            byte[si] |= 0x40    ; 加重标记(bit6)
call 0x3E65                     ; 三资源均值: (([si+4]+[si+6]+[si+8])/8) → call 0x5673
call 0x3E8E                     ; 信賴度动力学(见下)
si += 0x40; if si>=0x580: si=0  ; 22势力×64B 回绕
CS:[0xD1C] = si
call 0x5E80(al=4)
```

### 0x3E8E 信賴度/忠诚动力学(每势力每刻度)

```
bh = [si+0x2A]; if 0xFF return
call 0xECE0; if al<0x20 return          ; 概率门(~12.5%)
bx = bh/4
if byte[bx+0x425A]==0 return
ah = 0x17 - byte[bx+0x4253]
byte[bx+0x425A] -= ah (下限0)           ; 向基准值0x17回归
al = rand&0xF; cmp vs byte[bx+0x4253]
di = CS:[0xCFD](玩家势力); call 0x310A
; 对比玩家与该值, 单字节饱和±1调整 [bx]/[di]  → 疑似势力对玩家态度
```

表区: 0x4253(基准)/0x425A(当前) ≈ 武将区(0x42C0)前的附属数组

### 0x3EFD 单位轮询(主循环另支)

- 游标 CS:[0xD1E]，记录步进 0x20(32B)，上限 0x1800(=192条!) → 疑为城池数组遍历(192城✓)
- 字段访问形如 [si+0x857]/[0x858]/[0x85A]/[0x841] —— si 基址语义未定(静态歧义)
- [si+0x857] 每次递减(倒计时)；[0x85A] vs [0x841] 不等时回写表
- 0x3F2C~: es = cs:[0x9872]+计算段 → 读 es:[bx=[si+0x848]] &0x7F → [si+0x858] = 所在格地形码!
- 若 [si+0x841]!=0x18(非空) → call 0x3F74 大函数
- 然后 call 0x4194 / 0x4269

### 0x3F74 (单位AI主体, ss栈帧16B初始化FF)

```
call 0x3FA9 → [si+0x854]=ch(统计和)
jae → call 0x4028 else call 0x4057     ; 二选一决策分支
```

0x3FA9 内部: 需 [si+0x85B]!=0；扫4槽位(si+0x85C起,cl=4):
比较实体派系([bx+0x841]) 与 dl=[si+0x841]:

- 同派系跳过；空城(0x18)特殊路径
- 敌方且 [di+0x600]>=0x80 → 栈帧记 0xFE, ch+=[bx+0x858](兵力累计)
- dh==al 时记完整三元组([si],派系,兵力+1) → 疑为"相邻敌军评估/接敌报告"
结论(暂定): 0x3FA9=收集周围4方向敌情, ch=威胁合计; 之后按威胁选 0x4028/0x4057 行为

## ★内存布局定式(0x8CAE 实锤): 状态段偏移 = 文件偏移 - 0x80

| --- | --- | --- |

## ★AI决策内核破解 (0x4028/0x4057)

前置: 0x3FA9 扫4邻槽位得栈帧[bp..](敌情三元组/0xFE标记), ch=威胁合计→[si+0x854]
si 寻址确认: [si+0x840]=城池记录+0(attr) → si=城池索引k的辅助记录基址(k*32),
             城池本体在 0x840+k*32 —— 两表并行索引!
字段定名: [si+0x854]=威胁合计 [si+0x857]=行动冷却倒计时
          [si+0x858]=兵力 [si+0x85B]=启用标志 [si+0x85C..]=4邻槽位

### 分支A 0x4028 (无威胁路径)

清城attr高位(and 0x3F) → 若栈帧首槽==0xFE则重置冷却=0并返回
否则 or 0x80/0x40 标志位 → 若地形码[0x858]<1 → call 0x40C9(移动)+0x40B3

### 分支B 0x4057 (有威胁路径)

随机选一非空邻槽(rand&3 循环跳过>=0xFE):
  兵力[0x858]<=1 → 弱势: al=威胁合计+2-[0x858]>0 则 call 0x40C9(撤退移动)+0x40B3
                 且 玩家势力豁免(cs:[0xCFF]==派系则不动)
  兵力>1 → 强势: call 0x4155(★攻击, dl=随机数, dh=己方兵力) 后清冷却

### 0x40C9 移动例程要点

冷却[0x857]非0直接返回; 区分玩家/AI(cs:[0xCFF]);
玩家分支: call 0xCDE + 音效0x93(cx=0x26 call 0x8810) + rand&F+0x18;
AI分支: call 0x4575(疑寻路/可达判定, CF=失败) → 读[si+3]...

### 结论: 原版AI = 威胁感知→强弱判断→攻/逃/游走 三态机

与 Web 占位实现(最近敌城贪心)结构同族; 差异点: 原版只看4邻格、有兵力对比、
有冷却、有随机扰动。后续升级 ai.js 时按此三态机改写即可。

## ★BATTLE.DAT 最终定论：战斗开场脚本 VM (2026-08-23)

- **BATTLE.DAT(8192B) = 32块×256B 的战斗开场脚本**，不是图形/编制数据！
  - 块号 = 编制类型×4 + 攻守(0/1)，由 0xCBE5 在战斗屏 init 时 seek 块号×0x100 读 256B 到段 cs:[0xD30C]
  - 0x9A33 状态 init 置脚本 PC cs:[0xD311]=0；战斗帧循环 0x9FD4→**0xA426 逐字执行**
- **脚本字格式 u16le：op=低5位(0..18)，arg=高11位**；执行器 0xA436：`call cs:[op*2+0xA466]`（19 项跳转表）
- **op0=WAIT**：[0xD313]=arg，每帧递减归零前阻塞脚本（脚本流里大量 `arg/0` 对即"等待N帧"）
- **[0xD315] = VM 寄存器 R**（各 op 写入）；**op10=条件跳转**：子表 0xA59C=[je,jne,jb,jae...]，R 与 arg 比较，成立则取下个 word 为目标（低字节=0→近跳转 si=bh*2，否则 si=绝对字地址）
- 其余 op（写入 R 或操作部队）：op1=[0xD347]=ah、op2=[0xD33E]∈{0x3A,0x24,0x10}、op3=向 [0xD30E]+0x600 区 6 个单位下达命令([si+0x1B]=ah；ah=5→调 0xA8F6 列阵；al=7 全体否则单unit)、op4=R=[0xD346]、op5=R=1/2 按 [0xD33C] 与 0x1C 比较、op6/7=扫描单位 [si+0x1A] 取最大→R（镜头跟随前排）、op8/9/14/15/17/18=杂项读状态→R、op11/12=R=[0xD30A]+0x24/+4、op13/16=按 [si+0x24] 选 side 单位置 bit3+[si+0x1B]=al 并调 0xA8DE
- 脚本内容：两军列阵→逐单位移动命令→镜头平移（大量 WAIT）→待机。同编制攻守两块前段相似（对称布阵）
- **勘误**：此前「条目4B=(c,w,off) 精灵描述、off 指向 SCH」为误——那是把脚本 word 流误读成 4B 条目
- 战略图(主界面)军团标记另有两套：0x2B3C 旗帜贴图（es=[0x987A] 段，条目 (方向&3)+编制<<2 索引，4B=(c,w,off)，off+0x100 指向段内位图，0xFF=透明，0xD51F 盖章到 40×23 网格）与 0x2533 行军动画（es=[0x9874] 段，cs:[0x985A+节点*32+帧*4] 查表）。[0x987A]=[0xD46]+0x4200 段与 MMAP.MDL/MCH 装载区重叠（运行期数据，静态文件无法完整还原）

## ★可选#3 存档日期字段定位 (2026-08-24)

### 勘误：0xD9A/0xDA6 是文件名字符串，不是槽基址

- 反汇编 0xF4DF（读）/0xF593（写）实锤参数约定：**DS:DX=路径串、BX=内存段、SI=偏移、DI=长度、CX:AX=32位seek偏移**
- 故 0x8CAE 中的 `mov dx,bx`（0xD9A/0xDA6）是 **open 路径串的段内偏移**：cs:[0xD9A]="SINARIO.DAT"、cs:[0xDA6]="SAVE.DAT"（ah 标志选文件）；存盘 0x8CFF 恒写 SAVE.DAT
- **槽文件偏移 = slot × 0x56C0，无基址**；SAVE.DAT 大小恰为 4×0x56C0=0x15B00

### 槽内布局（存盘例程 0x8CFF 写入顺序）

| 槽内偏移 | 内容 |
| --- | --- |
| +0x000..0x3A | **CS:[0xCF0] 全局块原样镜像（0x3B 字节）** ← 含日期/税率/信赖 |
| +0x040..0x5F | 32B 标签（Big5 档名，es=[0x987c] 段） |
| +0x080.. | 状态段 [0xD52] 0x5240 字节 |
| 尾部 | 事件队列段 [0xD56] 0x400 字节 |

### ★月历字段真实语义（0x1D8E 日推进反汇编重解读）

- `[0xCF0]` word：**高字节=本月天数（查表 cs:[0x98AB+月]=标准历法[31,28,31,...]，2月28无闰），低字节=当日(1..当月天数)**
- `[0xCF2]` byte：日内子刻度 0..8（满9进位到下一层）
- `[0xCF3]` byte：每日时刻 0..23（满24进位到"日"）——旧笔记"CF2=旬/CF3=月"系误读
- `[0xCF4]` byte：**月 1..12**
- `[0xCF6]` word：**年（AD 纪元直存）**，≥1000 时回绕置998再+1
- 进位链：CF2→CF3→CF0.低→CF4→CF6；月末触发 call 0x5358 月结

## ★音乐系统定论：YNSOUND.COM 常驻驱动 (2026-08-24)

### 播放架构（实锤）

- **KI.EXE 经 int 0x61、D7OPEN/D7END/D7OVER 经 int 0xA1 调常驻音效驱动 YNSOUND.COM**（PLAY.BAT 只载 YNVSHELL.COM；驱动随盘另装）
- KI.EXE 0x24C：文件名表 @0xDDE=SOUND.DAT/0xDF0=BGM.DAT（重定位表项 0x45d/0x48e）；加载后取 cs:[0xD3C] 段，读轨道表 [bx]/[bx+2]/[bx+4]，AH=AL=5或6(bl<2) int 61h 播放，cs:[0xCF9]≠0 时 AH=7 停止；D7 系同构（mov ah,8; int A1h 查询 + ah,4 退出）
- **驱动硬件路径**（YNSOUND.COM 反汇编）：int 21h AH=25h 钩 **INT 8**，`mov al,0x36; out 43h` 把 PIT ch0 设 mode3、分频 0x0100（≈18.2Hz×70≈1.27kHz 快速节拍=音序器时钟），IRQ0 handler 内倒计数 [0xB69/B6A]、读 [0xB68] 触发声部事件，链旧向量+EOI(out 20h)；卸载恢复分频 65536(18.2Hz)
- 另有变址端口协议：dx=[0x97c]+4 窗口，out→busy-wait in(loop)→xchg ah/al→inc dx out——**硬件音乐卡**访问（卡型可配置，非 AdLib 固定端口 388/389）
- KI.EXE 本体无任何声卡端口（AdLib/PIT/Speaker 全零命中），仅 0xEB11 忙等式短哔(port 0x61 门控)=SFX；0xEC82 区=VGA DAC 渐变(0x3C9)

### BGM.DAT 文件格式（部分破解）

- BGM.DAT(20826B)/ENDBGM(2218)/OPENBGM(3424)/OVERBGM(684) 同构：
  - 头 word0=0，word1/word2=尾部两 chunk 偏移（如 OPENBGM 0xBE0/0xCE0）；中段 `30 00` + **5 个轨道偏移**（OPENBGM: 0xA5A/0x1D4/0x45E/0x85C/0x948）+ `22 00×3` + `D0 00`
  - 每轨起始 10B 前导一致：`80 0F A0 00 F0 00 00 06 D0 00`（疑 tempo/控制器初值），后接事件流
  - 尾 chunk = 16B 定长记录 ×N：`08 voice idx p1 p2 p3 00×9`
- 音符编码未破（需逐条反汇编 YNSOUND 解析器 0x1xx-0x7xx 区）；web 端结论：**音乐不复刻**（speaker.js 已覆盖 SFX 短哔），格式资料留档供后续

## 战斗屏指挥系统 (KI.EXE, 2026-08-25 逆向实锤)

### 单位/组内存布局

- 6 组 × 0x100：组基址 0x600/0x700/.../0xB00；每组 8 槽 × 0x20；组长=组首槽
- 字段：[+0x1A]=当前命令 [+0x1B]=待命令 [+0x16]=状态计时器 [+6]/[+8]=锚点 [+0x10/12]=坐标 [+0x14]=目标 [+0x1C]=目标指针 [+0x24]=组号 [+3]=HP类 [+4]
- tick 分发 @0xA785：[si]>=0x80→玩家侧(表@0xA7E7: cmd0→0xA92E/1→0xA953/2→0xA96D/3→0xA988/4→0xA99C/5→0xA9D0)；否则 AI 侧(表@0xA82D: 0→0xAA2C/1→0xAB9C/2→0xAB7C/3→0xAB39/4→0xABB2/5→0xAAED/6→0xAB39/7,8→ret 待机)；命令变更→重置计时器+回锚点
- 命令语义：0=待机类(回锚点后自动转7) 1/2/3=攻击类(3 受 [0xAB4F] 门控,关→remap 1) 4=接近目标[+0x1C]至距0x10 5=列阵 7=待机
- 命令入口 0xA4BF(al=组号7=全体, ah=cmd 1/2/3/5)：无 E8 调用者=仅开场脚本 VM 间接使用；0xA8DE=组内广播；0xA8F6=列阵(置[0xD349]=侧别+6组长cmd5)；0xA60D 按[+0x24]匹配群发(亦无调用者)

### 战斗主循环 0x9FA0

- 存 SP→[0xD340]；init 0xA1C5；loop{ 0xA156 输入(左键 bx=1/右键 bx=2；[0xD330]=X [0xD332]=Y；战场内换算图块[0xD338/33A]) →有点击 0xE453 查按钮号 → bx==1 走表A@0xC048(0xBFF2) / bx==2 走表B@0xC086(0xC01D) → 0xA426 脚本VM tick → 0xA065 帧 }；一方单位清零→0xA6FA→0x9FDC 结算(SP 回绕+士气扣减, 返回 al=[0xD349]=胜方)
- [0xD349]=战斗态: 0/1=侧别活动 2=禁止输入(0xA4BF 入口检查)
