# KI.EXE 游戏逻辑逆向笔记（进行中）

## 已破解：实时时钟系统 ★★★

游戏是**实时制策略**（系统菜单有"戰略速度/戰術速度"，印证时间自动流逝）。

### 时钟层级（KI.EXE:0x1D8E 主循环）

```
[CS:0xCF2] 子刻度   0..8      (cmp ,8；当前值>=8时进位)
[CS:0xCF3] 每日时刻 0..0x17   (cmp ,0x17=23)
[CS:0_CF4] 月       1..12     (cmp ,12)
[CS:0_CF6] 年(word) 上限~1000 (cmp ,0x3E8)
```

- `CF2<8` 时只自增；`CF2>=8` 时推进每日时刻并依次 call `0x9377`、`0x3E11`、`0x1E17`。
- 换月：查每月天数表 @0x98AC=[31,28,31,30,31,30,31,31,30,31,30,31]，call 0x5358 月结
- 每季首日（3/6/9/12月）：0x9377 内做季度视觉更新（调色板/背景图选择表 @0x265F）

### 势力轮询调度器（0x3E11）

- 每次游戏时刻进位处理1个势力，游标[0xD1C]，记录64B，共22个（si到0x580回绕）
- 势力记录字段：+0 属性(bit7=活跃, and 0xBF 清 bit6)；+4/+6/+8 三字求均值 /8 → call 0x5673；+0x19 条件置 FF；+0x21 word vs [+0x23]*16 比较
- 状态段：[0xD52] ← SINARIO.DAT 全量 0x56C0 原样驻留；文件头 0x3B 字节另存于 CS:0xCF0（时钟区）

## 月度结算 (2026-08-22 新增)

### 时间引擎最终语义 (主循环 0x1D8E)

| 变量 | 含义 | 范围 |
| --- | --- | --- |
| CS:0xCF2 | 子刻度 | 0..8（当前值达到8时进位；从0起共9次主更新） |
| CS:0xCF3 | 每日时刻 | 0..23 (每天24刻度，非"日"！之前笔记有误) |
| CS:0xCF0 | 日 | 1..当月天数 |
| CS:0xCF4 | 月 | 1..12 |
| CS:0xCF6 | 年 | word, >1000 回绕到 ~998 |

- 当月天数查表 va 0x98AC (`mov ah,[bx-0x6755]`, bx=月 → 0x98AC+月-1)
- 仅在 `CF2>=8` 的时刻进位分支跑：`9377` → `3E11`（势力调度）→ `1E17`（HUD日期重绘）；`CF2<8` 只自增并进入速度等待。
- 换月调 5358；月末那天 CF0 不再 ++ 而是 1DA3 分支直接换月

### 0x9377 = 换季视觉 (非经济!)

3/6/9/12月1日 且 [CF0]<=16 时轮转四季调色板缓冲:

- 春: 0x1934→0x18A4 / 夏: 0x18A4→0x18D4 / 秋: 0x18D4→0x1904 / 冬: 0x1904→0x1934
- 四组48B调色板常驻 CS:0x18A4~0x1963，当前生效组拷到 0x1964 工作区

### 0x5358 换月结算主函数

```text
for faction slot 0..21:
  if active:
    563B(本月累计支出)               # 从24位资金扣除
    53C6()                            # 以旧生产力、本月税率结算收入/兵源
    5609()
    clear faction[+0x1A..+0x1C]
全局链: 5695,585F,55A6,2BD9,5715,578F,22DB,2286,57FE
CS:[D10..D17]→[D08..]                # 最后才把次月政策转为本月

```

type4/type5建议额不是`+0x1A..+0x1C`累计支出；只有对话批准后由`0x39E8→0x563B`即时扣款。原版未见“每名武将20金月俸”。

### 0x53C6 收入与兵源

- 遍历192城，以`city[+1]`筛当前势力；收入和兵源都读取`city[+0x0E]`生产力word。首都距离档由`0x54FC`给除数。
- 玩家收入乘当前税率`CS:[D08]`；三类兵源分别受当前征兵设定`D0A..D0F`上限钳制。
- 非玩家收入在`0x5456`为原始24位收入右移1，即50%，不是Web旧25%。AI兵源是否并入由财政门控：`2*((军团总兵word>>8)+(累计支出24bit>>8)) < (实际收入24bit>>8)`。
- `0x5547`按城市Y坐标分三带，并按逐次位移取整分配基础兵源：
  - `y<80`：步=`base>>2`后再加其一半；弓=`(base>>3)>>2`；骑=余数（理想比例19/32、1/32、3/8）。
  - `80<=y<150`：骑=弓=`base>>3`，步=余数。
  - `y>=150`：骑=`base>>5`，弓=`base>>1`，步=`弓-骑`。
- 最终三兵源与势力`+4/+6/+8`做`0x55EC`饱和加法。

### 0x5695 生产力与上升率

该函数在财务结算后运行，因此本月收入必须使用更新前生产力。增减倍率直接取当前生产力word高字节`city[+0x0F]`，0按1；不是按城市type推导。它不执行内政官治理，`0x4194`只在逐城轮询链运行。

### 关键内存地址

- DS(=[CS:D52]) 城池数组`0x840`，32B×192；`+1`所属、`+0x0E`生产力word、`+0x10`上升率、`+0x11`防灾、`+0x12`城兵上限、`+0x13`城兵、`+0x19`内政官。
- 势力记录64B：`+0`属性(bit7活跃)、`+4/+6/+8`三兵源、`+0x1A..+0x1C`月累计支出。
- CS：`0xCFD`玩家势力、`0xD08`本月税率、`0xD10`次月税率、`0xD02..0xD17`收支/政策区。

## AI 调度器逆向 (0x3E11 链)

### 调用关系

- `0x1D0B` 每次主更新先调 `0x3EFD` 与 `0x25A3`，随后进入 `0x1D8E`；只有当 `CF2>=8` 发生时刻进位时，`0x1DEC` 才 call `0x3E11`（唯一调用点）。因此 `0x3E11` 是每游戏时刻一次、每次轮转一个势力槽，不是每主更新或每日一次。旧址注“0x1E04”错误，`0x1E04` 是速度等待分支。
- 五档战略速度的内核精确语义已闭合为**计时回调门槛**：`0x1DF8`读取`CS:[0xCFA]`，值0直接返回（最高速），非0先等INT61计时回调`0x356`置`D2C=1`，再等`D2D>=CFA`，然后清`D2C/D2D`。系统选单给该字节0..4，所以最低→最高等待计数为4/3/2/1/0。YNSOUND计时回调周期已闭合为约`3.43284ms`，故原版非零战略等待约为`13.731/10.299/6.866/3.433ms`；最高速无等待。它只改变战略主更新（`0x1D0B`）对墙钟的频率，不改变槽调度顺序、RNG或单次规则更新。Web表现档现为`240/140/80/40/12.5ms`（较旧`480/280/160/80/25ms`整体提速1倍），仍是便于观察的表现政策，不能写成原版绝对毫秒。军团移动继续由每次`0x25A3`的16槽轮询推进，不与每日结算绑定。
- **战术速度（2026-09-02 静态证据）**：战斗设置路径`0x1AB7→0x60A5`读取`CS:[0xCFB]`并连续左移四次，写入`CS:[0xCFC]`；战斗主循环的`0xA0F2..0xA110`与战略`0x1DF8`完全同构，按`D2C/D2D`等待`CFC`个INT61计数。因此其等待量是原始档位的16倍；结合五档UI，低→高的相对等待为`64/48/32/16/0`计时回调。YNSOUND `0x8B7`把PIT ch0设为`1193182/256≈4660.867Hz`，`0x913`每16个IRQ0经`0x93D`自修改far call调用一次KI以`INT61 AH=0Ch`注册的`0x356`，故一个计时回调周期为`256×16/1193182≈3.43284ms`。五档战术帧间隔实锤约为`219.70/164.78/109.85/54.93/0ms`；它只改变`输入→A426→A065`固定帧的墙钟频率，不能改变帧顺序/RNG/战果。Web已按该门控实现；最高速只保留每RAF最多12帧的浏览器防阻塞上限。
- 0x3EFD 由 0x1D13(7443d) 调用 —— 主循环另一分支

### 0x3E11 势力调度器结构（2026-09-01闭合）

```text
call 0x31AE                         ; 全局战略事件时间轮，不是AI决策器
si = CS:[0xD1C]                     ; 势力游标
ds = CS:[0xD52]
if byte[si] >= 0x80:
    byte[si] &= ~0x40               ; 每轮清严重财政不足位
    threshold = byte[si+0x23]*8+24  ; +0x23=据点数
    moneyQ256 = signed word[si+0x21]; 24bit资金算术右移8位
    if threshold >= moneyQ256:
        byte[si+0x19] = 0xFF        ; 清当前战略目标
        if threshold/2 >= moneyQ256:
            byte[si] |= 0x40        ; 严重财政不足状态
call 0x3E65                         ; 三预备兵合计/32累加月支出
call 0x3E8E                         ; 外交官预算维护关系
si += 0x40; if si>=0x580: si=0      ; 22势力槽回绕
CS:[0xD1C] = si
call 0x5E80(al=4)                   ; 玩家资源面板重绘
```

结论：`0x3E11` 本体没有候选搜索、目标选择、内政分配或多战线调度。目标主要由 `0x2BD9→0x2EFB` 在开局/月结排type1事件，再由 `0x31AE→0x320C→0x3526` 提交；`0x3E11` 只会因财政不足清目标。

### 0x3E8E 外交官常态关系维护(每势力槽)

```
bh = [si+0x2A]; if 0xFF return
call 0xECE0; if al>=0x20 return         ; 有外交官便先消费，概率门(~12.5%)
bx = bh*0x20                         ; BH索引清BL后右移3次

byte[bx+0x425A] -= ah (下限0)           ; 向基准值0x17回归

di = CS:[0xCFD](玩家势力); call 0x310A
; 对比玩家与该值, 单字节饱和±1调整 [bx]/[di]  → 疑似势力对玩家态度
```

表区: 0x4253(基准)/0x425A(当前) ≈ 武将区(0x42C0)前的附属数组

### 0x3EFD 单位轮询(主循环另支)

- 游标 CS:[0xD1E]，记录步进 0x20(32B)，上限 0x1800(=192条!) → 疑为城池数组遍历(192城✓)
- 字段访问形如 [si+0x857]/[0x858]/[0x85A]/[0x841] —— si 基址语义未定(静态歧义)
- [si+0x857] 每次递减(倒计时)；[0x85A] vs [0x841] 不等时回写表
- 0x3F2C~: es = cs:[0x9872]+计算段 → 读 es:[bx=[si+0x848]] &0x7F → [si+0x858] = 所在格地形码!
- 若 [si+0x841]!=0x18(非空) → call 0x3F74 大函数
- 然后 call 0x4194 / 0x4269


### 0x4028 运行态城attr高位

先清`city[+0]`高位(`AND 0x3F`)。工作行首槽为`0xFF`表示无威胁/候选，只清冷却并返回；`0xFE`表示存在交战邻城，置bit7；小于`0xFE`表示已写入与势力战略目标一致的邻城候选，置bit7+bit6。随后以本城运行兵力`[+0x858]`决定是否继续`0x4057`。SINARIO静态`raw[0]`仅含四方向邻接低位，不能替代这些运行高位。

### 分支B 0x4057 (有威胁/候选路径)

随机选一非空邻槽(rand&3 循环跳过>=0xFE):
  兵力[0x858]<=1 → 弱势: al=威胁合计+2-[0x858]>0 则 call 0x40C9(撤退移动)+0x40B3
                 且 玩家势力豁免(cs:[0xCFF]==派系则不动)
  兵力>1 → 强势: call 0x4155(★攻击, dl=随机数, dh=己方兵力) 后清冷却

### 0x40C9 移动例程要点

冷却[0x857]非0直接返回; 区分玩家/AI(cs:[0xCFF]);
玩家分支: call 0xCDE + 音效0x93(cx=0x26 call 0x8810) + rand&F+0x18;
AI分支: call 0x4575(疑寻路/可达判定, CF=失败) → 读[si+3]...

### 结论: 原版AI = 威胁感知→强弱判断→攻/逃/游走 三态机

与 Web 占位实现(最近敌城贪心)结构同族; 差异点: 原版只看4邻格、有兵力对比、
有冷却、有随机扰动。后续升级 ai.js 时按此三态机改写即可。

## ★可选#3 存档日期字段定位 (2026-08-24)

### 勘误：0xD9A/0xDA6 是文件名字符串，不是槽基址

- 反汇编 0xF4DF（读）/0xF593（写）实锤参数约定：**DS:DX=路径串、BX=内存段、SI=偏移、DI=长度、CX:AX=32位seek偏移**
- 故 0x8CAE 中的 `mov dx,bx`（0xD9A/0xDA6）是 **open 路径串的段内偏移**：cs:[0xD9A]="SINARIO.DAT"、cs:[0xDA6]="SAVE.DAT"（ah 标志选文件）；存盘 0x8CFF 恒写 SAVE.DAT
- **槽文件偏移 = slot × 0x56C0，无基址**；SAVE.DAT 大小恰为 4×0x56C0=0x15B00

### 槽内布局（存盘例程 0x8CFF 写入顺序）

| 槽内偏移 | 内容 |
| --- | --- |
| +0x000..0x3A | **CS:[0xCF0] 全局块原样镜像（0x3B 字节）** ← 含日期/税率/信赖 |
| +0x040..0x5F | 32B 标签（Big5 档名，es=[0x987c] 段） |
| +0x080.. | 状态段 [0xD52] 0x5240 字节 |
| 尾部 | 事件队列段 [0xD56] 0x400 字节 |

### ★月历字段真实语义（0x1D8E 日推进反汇编重解读）

- `[0xCF0]` word：**高字节=本月天数（查表 cs:[0x98AB+月]=标准历法[31,28,31,...]，2月28无闰），低字节=当日(1..当月天数)**
- `[0xCF2]` byte：日内子刻度 0..8（满9进位到下一层）
- `[0xCF3]` byte：每日时刻 0..23（满24进位到"日"）——旧笔记"CF2=旬/CF3=月"系误读
- `[0xCF4]` byte：**月 1..12**
- `[0xCF6]` word：**年（AD 纪元直存）**，≥1000 时回绕置998再+1
- 进位链：CF2→CF3→CF0.低→CF4→CF6；月末触发 call 0x5358 月结

## ★音乐系统定论：YNSOUND.COM 常驻驱动 (2026-08-24)

### 播放架构（实锤）

- **KI.EXE 经 int 0x61、D7OPEN/D7END/D7OVER 经 int 0xA1 调常驻音效驱动 YNSOUND.COM**（PLAY.BAT 只载 YNVSHELL.COM；驱动随盘另装）
- KI.EXE 0x24C：文件名表 @0xDDE=SOUND.DAT/0xDF0=BGM.DAT（重定位表项 0x45d/0x48e）；加载后取 cs:[0xD3C] 段，读轨道表 [bx]/[bx+2]/[bx+4]，AH=AL=5或6(bl<2) int 61h 播放，cs:[0xCF9]≠0 时 AH=7 停止；D7 系同构（mov ah,8; int A1h 查询 + ah,4 退出）
- **驱动硬件路径**（YNSOUND.COM 反汇编）：`0x8B7`以int21 AH=35h/25h替换**INT 8**，`mov al,0x36; out 43h`把PIT ch0设mode3、除数`0x0100`（`1193182/256≈4660.867Hz`）；`0x913`的IRQ0 handler每次执行音乐倒计数。计数器`B6A`每16个IRQ在`0x93D`执行一条自修改far call；`INT61 AH=0Ch`于`0x2FB`把KI传入的`DS:DX`写入该指令的偏移/段操作数`0x93E/0x940`，故KI的`0x356`回调频率约`291.304Hz`、周期约`3.43284ms`。另一个计数器`B6B`每256 IRQ在`0x94C`跳回旧INT8，维持约18.2Hz BIOS时钟；不能把它与游戏计时回调混同。卸载时恢复旧INT8和PIT除数65536。旧笔记把`B69`音乐节拍、`B6A`游戏回调和`B6B`旧BIOS链混为一谈，现已纠正。
- 驱动的合成器端口已闭合到**Sound Blaster Pro双OPL2兼容端口布局**：COM静态初值`[0x97C]=0x0220`，`0x890`按`out base,index / out base+1,data`写左FM，声部3..5用`base+2/+3`写右FM；`0x8A7`访问`base+4/+5`，与SB Pro mixer index/data完全一致。公开SB Pro端口表也给出220/221左FM、222/223右FM、224/225 mixer。故这不是PC speaker PCM，而是左右两颗OPL2的立体声FM路径；Web若要还原ID3应按双YM3812寄存器写入仿真，而非继续用单振荡器扫频。该硬件身份来自本地驱动指令与公开端口表交叉核对；产品运行时仍不得依赖外部网页。
- 另有变址端口协议：dx=[0x97c]+4 窗口，out→busy-wait in(loop)→xchg ah/al→inc dx out——**硬件音乐卡**访问（卡型可配置，非 AdLib 固定端口 388/389）
- KI.EXE 本体无任何声卡端口（AdLib/PIT/Speaker 全零命中），仅 0xEB11 忙等式短哔(port 0x61 门控)=SFX；0xEC82 区=VGA DAC 渐变(0x3C9)

### BGM.DAT 文件格式（部分破解）

- BGM.DAT(20826B)/ENDBGM(2218)/OPENBGM(3424)/OVERBGM(684) 同构：
  - 头 word0=0，word1/word2=尾部两 chunk 偏移（如 OPENBGM 0xBE0/0xCE0）；中段 `30 00` + **5 个轨道偏移**（OPENBGM: 0xA5A/0x1D4/0x45E/0x85C/0x948）+ `22 00×3` + `D0 00`
  - 每轨起始 10B 前导一致：`80 0F A0 00 F0 00 00 06 D0 00`（疑 tempo/控制器初值），后接事件流
  - 尾 chunk = 16B 定长记录 ×N：`08 voice idx p1 p2 p3 00×9`
- 音符编码未破（需逐条反汇编 YNSOUND 解析器 0x1xx-0x7xx 区）；web 端结论：**音乐不复刻**（speaker.js 已覆盖 SFX 短哔），格式资料留档供后续
