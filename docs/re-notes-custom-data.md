# 自定义剧本、势力、军团、关系、地图与快照的数据基础

本件是字段/引用/生命周期研究，不是编辑器、任意地图扩容或DOS存档导出器实现授权。
[实体字典](re-notes-entity-fields.md)唯一维护武将与据点32B详情；本件维护势力64B、军团64B、头128B和跨资源关联。

## 范围与可复核方式

- 只认可KI明确指令及原始非存档数据；截图/既有Web/测试仅作待审对象。unknown不等于unused；有字段表不等于所有写回事务已闭合。
- 不读写/探测任何实际用户存档，仅静态审查KI文件I/O，不执行保存/载入。正式Web仍用IndexedDB四槽，读档先回标题；不恢复旧服务端接口。
- VA=文件偏移−200h、near rel16回绕；所有“范围”区分存储容量与有效槽。各节编号按“势力§ / 军团§”区分。
- [focused工具](../tools/verify_entity_fields.py)固定白名单，只输出stdout；标准库实现几何检查，不依赖旧Web权重或生成数据。`python -X utf8 -B tools/verify_entity_fields.py`，加`--distributions`打印官方逐字段统计。验证不证明全程序unused。
- 未来新增章节可作为内容组织需求；本批只证明原版4×56C0h，Web五库20章属于现有内容架构，不是KI任意章数支持。编辑、重排ID、动态扩容、旧快照迁移均需另立明确产品/引用完整性方案。

## 势力 1. 存储布局与容量：不能任意扩容

`8CAE..8CFE`：AL章节/槽号×56C0h；先读3Bh到CS:CF0，再从章/槽+80h读5240h到[D52]状态段，最后读400h到[D56]事件段。`8CFF..8D4C`静态写出同样3Bh头、另写+40h的20h标题串、状态段和事件段；不是原样写完整80h头。未执行这些函数。

- 势力：章+80h，状态段+0000h，24×40h=600h。
- 关系：章+680h，状态段+600h，24×24=240h。
- 城市：章+8C0h，状态段+840h；正常调度/经济扫描192城。
- 24是储存容量；`3E4F cmp si,580h`、`5386 cmp cl,16h`、`78FC/7B86 cmp si,580h`证明势力正常轮询/月结/列表为22槽（0..21）。不是按头部势力数遍历。
- 18h=24是空城/中立目标哨兵，不是可编辑第25势力。`3639/3669`遇18h直接返回，不能索引关系第24行。
- FF是多字段空值；军师空值却是7F，君主/首都/外交官不能一概用同一sentinel。
- 后三章活动势力数11/6/4，不表示余下固定槽可删除。槽22、23全零但关系行仍有24字节；不能因无正常轮询就当可自由利用。

## 势力 3. 影响AI的隐藏联动、单位与写回边界

### 势力 3.1 资金与财政状态（实锤）

资金解码：`u=loWord+(hiByte<<16); signed=u>=800000h ? u-1000000h : u`。

- `560B 03 44 20;560E 12 54 22`为24位加；`5611 cmp dl,9`采用有符号JL/JG，再比较低word FE98h，最终上封 `09FE98h=655000`。
- `563D 29 44 20;5640 18 54 22`为24位减；`5649 cmp dl,F6h`采用有符号JG/JL，低word门槛0168h，最终下封 `F60168h=-655000`。
- `6851 mov al,[si+22];6854 98(CBW);6855 mov dx,ax;6857 mov ax,[si+20]`证明显示也按有符号高byte扩展。截图-1889只是线索，不是本证明。
- 这些是加法入口上封、减法入口下封，不应宣称任意非法24位输入都被两向修复；未来编辑器正常数值范围与原始bits模式应分开。
- `3E11`先消费事件，`3E1D`只在active时清bit6，令T=城数×8+24，signed16 moneyQ256=word[21]；若T>=moneyQ256则target=FF；若floor(T/2)>=moneyQ256再置bit6。此段0 RNG。
- `4426`重新由军团所属构造faction指针，`442F test [bx],40h`仅使状态2跳过+17优先槽，转消费+16。不是通用「破产自动撤退」，也不是7778的君主身份档。
- `3E65`完整24位求三池和、右移5，`5673`加到累计支出上封655000；`5358`逐22槽，活动者先扣累计支出，再经济计算/加收入，再清累计支出。

### 势力 3.2 三池及士气（实锤到字段，极端值策略未批准）

- `55EC add ax,dx; carry或ax>FFDC则ax=FFDC`，即预备池正常加法饱和65500单位=655000人。三池显示直接证据：`5F85 add si,4;5F88 mov cx,3;5F8E mov ax,[si];5F90 mov dx,10;5F93 mul dx`，每轮SI+=2后显示，明确三个池均×10。
- `67F2/6812/6832`原UI征兵输入上限10000人；`67FC/681C/683C mov bx,10;div bx`写三兵word，所以原word为十人单位。`689D..68A8`展示三个征兵word时×10。
- 编成`6EC9`读取三个池，兵种表顺序按1/2/3映射，单队候选至少50底层单位，再实际划拨；相关已闭合分兵链以内政/外交Skill §6为索引，本轮未重逆六队全过程，不授权新分兵算法。
- 士气`263D add legion[6],10`后与faction[1D]比较截顶，且`6F77`直接作为编成初值。只证明官方200下路径，编辑到极端byte需独立溢出审查。

### 势力 3.3 好战、实力和目标（非UI五等级阈值）

`2EFB`第一候选需：目标不同；`min(nCities*16+64,061Ah)<signed word[21]`；raw关系不大于 `80h | (b + floor(b/2) +20)`；己方实力不小于 `enemy - floor(enemy/4)`。最后这个精确整数式不是任意舍入的3/4。

`3091`：R=(骑>>2)+(弓>>2)+(步>>2)；若highByte(R)>=城数则R=2000；再R>2000也设2000；若**unsigned**word[21]<=19则R=0。不是简单min(R,城数×256,2000)，也不是signed资金判断。与`2F25`的有符号JGE不能混同。

`64A0`玩家提案读取同一好战度，关系低7值与`2*b+20`比较；理由还读target及signed word[21]。`57FE`赤字处罚检查**word[21]负值取负后>=39**（不是资金低word>=39），再消费RNG，`(rng&15)<b`才试排type13，再一次RNG来自随机入槽。旧kernel「取资金低word绝对值」不精确。

目标与消息边界：

1. `2D58`active（含玩家）走关系更新/事件候选，`2F68→2FB1→2FBF`只排type1；随机入槽先耗1 RNG，即使满槽失败也已耗。
2. `31BE`出队→`320C→3526`。玩家相关先最终君主对白返回（`3588 call 8810`），`3593`才写非玩家发起者+19，`35A3→3639→3644`提交双向交战。不是入队时提交。
3. `2D8E..2DB7`月度会清不再匹配第一交战候选的旧目标；`2F71`空城分支使用18h、单独资金门槛，无关系矩阵第24行。
4. 一次性+16/+17是城槽，不是+19的平行副本。`4436/443F xchg …,FF`是消费即清。
5. 首都变化应复用原迁都事务；已闭合索引`33EA→4502/6A3D`：影响军团旧首都目标和路径重算标记。此批未逐条重读该整段，**不交付可直接编码的迁都补丁算法**。

## 势力 5. 关系矩阵：有向byte、真实文案分档、各操作方向

### 势力 5.1 寻址与有效域

`3119`输入SI=A*40h、DI=B*40h：SI/4+SI/8=A*24，再加B，最后`3132 add bx,600h`。所以cell为 `600h+A*24+B`。文件额外加80h。不是三角压缩矩阵，不能自动对称。

bit7=1和平，bit7=0交战；低7位为关系数。正常增益封100、减益封0，实际原字节可保留0..255；FF对角是结构数据，不能当「亲密127」普通关系。

### 势力 6.1 章节样本与玩家身份不能只改一个byte

**官方原始数据复核：** `原版/SINARIO.DAT`实际88832B=`4*56C0h`；每章`+11`依次00/01/02/03，而不是01/02/03/04。四章头`+00=01,+03=01`同时成立，容易把初始时刻误当日；年份分别为`C4 00 / D0 00 / D4 00 / E1 00`（196/208/212/225），高byte恰为0不是年字段只占1B的证据。正确位宽取上表的`1DAA/1DB8`word指令。

正式选定玩家的原始窗口为：

```text
1AFD MOV AH,[BX+2]              ; BX=所选势力记录指针
1B00 CMP AH,7F
1B03 JE 1B08                   ; 仅跳过普通军师人数扣减
1B05 DEC BYTE [BX+18]
1B08..1B10 AX=(AH<<8)>>3; SI=AX ; 军师索引*20h
1B12 MOV BYTE [SI+4240],0       ; 自创/普通军师都清attr
1B17 MOV CS:[CFD],BX            ; 头+0D..0E玩家势力指针
1B1C SHL BX,1
1B1E SHL BX,1
1B20 MOV CS:[CFF],BH            ; 头+0F玩家势力索引
```

`5907`一般招募的玩家分支直接读取CFD，多个对白/规则路径又使用CFF，所以只改头`+0F`或槽名不是完整“切换玩家”事务。还须区分开局军师退出普通将池的生命周期与运行快照；不能对已有快照重复执行上面的扣数/清attr。第127条自创与城防复用证据唯一维护于[武将§1.3](re-notes-entity-fields.md#general)。

`DS:4200 = 2240 + 127*40`是临时城防槽，后接武将表，不是额外第129军团。`4F8C BX=4200;4F95 +2=7F;4F99 +6=FF`。官方武将127记录四章相同：

`00ffa1d0a1d0a1d0a1d0a1d0a1d00000000808080000000000ff0000ffff0300`

其存在并不授权把7F编成普通活动军团。主将byte raw 0..255，正常普通索引0..126，7F特殊；80..FF没有本报告支持的合法主将语义。

## 军团 3. slot、主将与特殊条目的完整性

`6E92..6EAD`用武将真地址减4240、乘2，得到军团同号槽；`6F2A..6F3F`又由军团地址计算同号武将、把general+17置1并写军团+2。玩家编成6CB5..6CBD同样直接由武将地址计算军团槽，而非任意分配空槽。

三类消费者不同：

1. **主将byte消费者**：52DB拿军团+2找能力；8099拿+2找头像/姓名；4EBB/4EC1拿+2组TALK29参数；2949用+2判断是否君主。
2. **slot消费者**：4CCA..4CD4由军团地址换算同号武将+1F评分；CBE5→CC02..CC14从D30敌军团地址计算slot，读取`4240+slot*20+16`选脚本。291A的2938..2940先算同号武将；随机阈值2960也读该同号武将+1F，而不是通过+2重新找。
3. **回归/注销消费者**：2A8A..2A8E按延迟军团slot清同号武将+17；4651正常解散同样按slot。只改+2会造成“显示A、能力A、脚本B、回归B”。

`291A`的去向分派：无首都直接走29C3；君主、同势力、中立接收短路走2977；否则一次ECE0，低7位与同号武将+1F/2+40比较。2977先移除地图占格、status=08、03=48，再4689减少势力军团数；TALK31/32返回后才回外层。2A7E每次该槽访问减03，0时清军团status和同号武将状态；势力已灭则武将所属FF，否则玩家方TALK35→个性选择器198。**48是槽访问次数，不是48天；队列物理仍占原军团槽，不能filter后压缩。**

29C3被俘/退场是另一路：必要时移除占格/减军团数，清军团status，将同号武将+17=4，交换所属并写原属+1D，再按原attr/旧势力状态及玩家关系显示TALK33/34/67、个性对白。没有在这些退出处清空所有64B，不能从残留兵种/坐标认定status0仍活动。

## 军团 4. 目标、移动、接触与写回：为何只改坐标不成立

### 军团 4.1 正常指示/换边

玩家`7F90→7FDB`选择目标后，普通命令两种战斗方式都写23=0、0B=1、20=目标；委任额外置bit2，战术指挥清bit2，解体命令23=11。返回后7FB4调用状态机4325、7FB7置bit1。不能只写一个UI target，或把所有字段强行同轮清零。

`47BB`当前在节点时从491B取下一边/stride，取edge首/末point地址写0C、edge地址写0E、清bit0、写stride。**当前已在edge时保留0C当前point，仅选择朝向写0A并置bit0**；新目标为+6端点即−4，为+8端点即+4，否则先从端点搜索再确定方向。没有“把当前位置最近格当新节点”的原版入口。

`28CC`通过目标X/Y扫描192城取得目标node，并写14/16/18；6F86新编从首都直接初始化当前及目标node/坐标。其它退点分支（4780/4789）先写14/20再置重寻位，不在该窗口写16/18；未来保留快照不能擅自把暂时滞后的镜像当损坏强制清目标。

### 军团 4.2 动作与占格

```text
25A3: 轮到活动槽 -> --0B
      if 0B==0: 0B=1E; status&=DF; 2662()
      2600日费用/节点士气; 264A接触倒数
```

2708首先查候选格计数，有占格则2831找前127槽活动军团，比较其坐标和势力；异势力先进入接触。随后仅bit0且候选tile在CE..DD时2880检查当前edge对应端点城。被阻挡/进入接触时**尚未写候选坐标**。可通过则2764..2774写pointer、point、X和Y低byte；边端切换27A2根据stride±4取edge+8/+6，0E写node，再按node×4找城市word坐标。

### 军团 4.3 接触、兵力与消息边界

- 2831/2880初次设置bit5及03=12；264A同槽可减到11。03>1只请求音效，等1且动作到期才4A7B/4ADE；接触类型由重新检查现场得出，无独立field/siege字节。
- 4A7B/4ADE清bit5/03后分流。玩家未委任且真实参战军团存在才显示接战TALK29/27/28，`8810`返回后进1B5A战术；无真实守军的4200临时军一律按城兵分成六队type3/士气FF做速算。不能让未来编辑工具丢掉等待上下文并直接补一场“推测的”战斗。
- 5285按六队byte1/byte2算战力，**不是先用总兵均分**；52D7每方能力分支可能消费1次RNG。51F9..5245六轮胜/败交错共12次RNG，逐队写兵数；5249/524C写总兵，5265/527D按比例写士气，再474A重算/继续或撤退。首队有最低1的战果分支，不等于可以让所有其它队数据任意缺失。
- 战术9E97裁剪原记录；9F2C累计对象幸存，9F58合并临时余兵+幸存回各原队byte1、合计并按旧总兵比例写士气；总新兵为0时9F84直接到9F98，此窗口**不交换写回总兵**，后续1BBA→474A→6FD2再重算。因此“任何瞬间总兵都必等于六队和”不是全状态定理，编辑器不能在消息/战术中途作任意规范化。
- 战后474A先6FD2令0B=1、重算总兵/周期/标识；士气0或首队0失败转291A；退点写14/20、bit1及23=8/10但不瞬移。通用AI、消息返回、撤退队列与RNG不能拆成互不相干的表编辑。

### 军团 5.1 8CAE/8CFF静态I/O闭合

```text
8D40 BX=[D56]; SI=0; DI=0400; CALL E3A6
```

E38C→F4DF明确DOS INT21 `3D00 open-read / 4200 seek / 3F read / 3E close`；E3A6→F593明确`3D02 open / 4200 seek / 40 write / 3E close`，没有执行。wrapper保存寄存器使调用后AX/CX仍是原seek基址；不能把DOS read返回长度当下一seek基址。8D4D是标签构造，不是完整加载；kernel旧标题“8CAE写/8CFF读”、附加80h尾块和“文件偏移=DS偏移”都与原码/官方文件长度冲突。

### 军团 5.2 必须保存的关联不等于可重建显示缓存

- CS头中的日历CF0..CF7、军团游标D18→槽头28h、势力游标D1C→2Ch、城市游标D1E→2Eh、事件cursor D20→30h均在3Bh传输范围；25AD/25F6、3E14/3E5B、3EFD/3F6F、31C7/31D5提供消费者/写回。D1A专门语义本轮未追，不以邻近游标强行命名。
- 雨云吸引边界D22/D24/D26/D28→头32/34/36/38，248A实读；不要混同物理回绕X[-16,400]、Y[-16,272]。地图对象32×16B在状态段；23FF只分配前16，2459扫32且仅SI>=2140的后16调用移动248A，+0C/+0D剩余/重装，+8/+A含相位/速度。六队/回归槽不能覆盖此区。
- 事件尾不是“可随便加JSON”的空白：2FBF/301C往D56写两个word=4B；31C7从D20读一条、推进4，再间接分派，TALK返回后才继续外层；2BD9把后300h前移并清末100h、cursor归0。空槽顺序/事件payload、cursor和原有消息边界均有规则意义。
- DOS也不是任意运行点的完整机器快照：CS:31AD事件执行节拍、自修改参数、战术对象池/VM、栈中的消息续段等不在上述三个状态块；不能把Web sidecar字段一一投射到DOS空隙。本文未穷尽所有非保存执行上下文，不设计跨战术/消息中途的DOS修改恢复器。

### 军团 5.3 8AEA到底重建什么

`19CA`战略资源装配中1A2F..1A4A清独立384×256占格计数平面。89F0先192城着色8A1E，再127军团逐条8AEA：

```text
8AEA CMP BYTE [SI],80h; JB return
8AEF AX=WORD [SI+12h]
8AF2..8AFC AX = Y*24
8AFE ADD AX,CS:[9872]
8B03 ES=AX
8B05 BX=WORD [SI+10h]
8B08 [SI+1Ch]=AX
8B0B [SI+1Ah]=BX
8B0E INC BYTE ES:[BX]
```

这是**仅在军团记录中重建1A/1C地图far pointer，并重建独立占格计数**；不重寻道路、不改0A/0B/0C/0E/14/1E/20/23，不恢复/推导“接战类型”，不重算总兵。无论同一次进程重新分配段地址还是其它进程，旧far pointer不能直接使用。标准恢复依赖现有X/Y和活动状态合法。

静态地图→同顺序拓扑可以重新构建，但**已保存point/edge/node是该拓扑地址身份的一部分**；换地图或改变道路扫描顺序后同一0C地址可能指另一条路，不能声称重建资源便自动恢复旧行军。修改内容与恢复旧快照需未来单独身份/迁移设计，未获本轮实施授权。

### 军团 5.4 DOS RNG：保存块不包含，标准读档继续当前流

已核查：

```text
003A E8 2E 00          CALL 006B    ; 程序启动先执行
0040 CALL 005B                     ; 随后进入装配/标题流程
005B..0067 CALL 0A1C;19CA;1A6E;19CA;1BE0
006B 启动初始化函数
0077 E8 08 EC          CALL EC82
EC87 MOV AX,CS; EC89 MOV DS,AX
EC91 BX=ECFE; EC94..99初始化前256表byte
EC9B AH=2; EC9D INT 1A ; BIOS RTC
ECD2 [ECFC]=AL         ; addend
ECD7 [ECFD]=AL xor BL  ; index
ECE2 MOV AX,CS; ECE4 MOV DS,AX
ECE6 BX=ECFE; ECE9 AL=[ECFD]; ECEC XLAT
ECED AL += [ECFC]
ECF1 [ECFC] += 89h
ECF6 [ECFD]=AL
```

表为CS:ECFE..EDFE（257B，洗牌可涉及第257字节），addend/index为ECFC/ECFD。它们**不是DS:D52内同数字offset，也不是D56事件区**。8CFF仅CS:CF0..D2A、D52、D56及标签；8D4D没有RNG打包。8B40→8CAE和标准返回1ADE→1B2C、战略恢复89F0没有读档重播种/恢复RNG步骤。扫描KI的near-call候选，EC82仅0077，已核查对应启动指令；这不是全程序间接调用不存在证明。

**可成立的局部结论：** 标准同进程读档不会恢复保存时的RNG，而延续当前进程CS随机流；在新进程读档之前，该进程已经经过启动RTC初始化。不能从“不保存”推出每次读档新建种子、固定种子、从存档日期播种，或推测DOS可完全确定性重放。任意未知入口/外部修改行为未知。Web保存完整RNG是明确架构差别，不是发现了DOS隐藏RNG字段。

## 军团 6. 地图、拓扑、道路点与AI代价

### 军团 6.1 原始资源分层

- MMAP.MAP是RLE地图排列。F655 seek4跳头，F600..F634逐byte：连续相等双byte后下一byte作额外重复计数，0只转下一组；解包结果98304=384×256。首4B数值也为98304；代码这一窗口跳过头而非依它开放任意尺寸。
- MMAP.MDL/MCH是原始定长资源，87AF/87BB经E378整文件读；MCH放MDL基段+800h，即物理+8000h。不是也用MAP RLE。MDL大小8000h；MCH大小A832h，不可把整个MCH强行当整数个160B军团标识（其后还有描述/接触图案等）。本轮不扩成整图像解码。
- 军团方向/势力标识由2B2A读09+08交D4C7，资源样式与地形tile排列不同。BATTLE地图、KYOGRF景观也各自独立，见军团§6.5。

### 军团 6.2 节点顺序、邻接和位宽

E4CE扫描X=0..383、逐行Y byte完整256行，CB<=tile<D4时调用E57F并递增节点号。E57F依次左/右/上/下探1格，再2格；E717按相同四槽顺序生成node的四个word。

实测官方四章各192城的X/Y顺序与上述扫描顺序逐项相等，**不是只比较坐标集合**；四章城邻接集合与从原始MAP转录构图得到的254边完全匹配（768条0 mismatch）。城市邻接+1C..1F是紧凑索引顺序；道路node四槽保留罗盘槽。此次验证的是**集合一致，不是两种四槽在数组下标上逐项相同**，不可拿node方向bit直接覆盖城attr位。

E717最终拓扑地址：node自0000，每个8B；edge自0800，每个10h；point自2000，每个4B。每个node邻接word低14位为edge地址，高位4000/8000表示该边两端；0是空邻接，**node地址0本身却有效**。当前192节点占0000..05FF；当前254边占0800..17DF；5526点占2000..7657。

|edge字段|本轮闭合|
|---|---|
|+0 word|首point地址（E79E）|
|+2 word|末point地址，E7A8从下一个分配地址减4写入|
|+4 byte|AH计数所得边代价，不是word；4A3D读取|
|+5 byte|清零工作区形成初值；独立语义未闭合，不可复用|
|+6/+8 word|source/target node地址（E78B/E7EE）|
|+A/+C word,+E/+F byte|构图记录的minX/maxX/minY/maxY（E7B1..E7CA，E921..E94C维护）|

point=`x:u16,y:u8,classFlags:u8`；E961接受B8..DD：B8/B9→1、BA..CA→0（CA另置80）、CB..D3→3、D4..DD→4；特殊首点再置40。这些tile索引参与规则，不能只因图像相似就重新编号。

### 军团 6.3 新纠错：edge+4的完整局部生产→消费窗口

以下为可复核关键连续块与控制条件；完整函数范围E77D..E81B、E81C..E960、E961..E992、491B..4A7A已读原字节。省去的坐标边界统计不修改AH。

真正寻径消费者：

```text

49C7 JAE 49E3

49CD CMP BYTE ES:[SI+0841h],<搜索势力> ; 49D2自修改立即数，由493B写

4A35 JMP 4A3D
4A37 DI=[BX+6]; BP=0004h

4A60 [BX]=DI                      ; 队列node

4A68 [BX+6]=AX                    ; entering edge
```

**精确区分三个量：**

1. point数组实际分配条目数N：`(last-first)/4+1`。
2. 静态edge代价byte：`u8(N - (特殊首点?1:0))`。当前官方254边首tile均D4..DD，故均N−1；点总数5526，代价总和5272，范围5..83。edge0为15点、代价14。
3. 实际行军动作/被消费坐标数：由0C、stride、bit0、端点class、接触及城市所有权决定；2708既可能消费首点，也可能在敌城末点写坐标前返回。**不能由代价N−1推断少移动一格**。更不能把edge代价直接当全路径代价：49DC每扩展城市节点另加4，非己方路径还会ADD A6/OR 8000，16位语义须保持。

此次纯probe构图的几何/连接/点序在所查原码范围复核并对官方城市匹配；既有probe的`weight=len(points)`与原AH写回不一致。因此旧“所有有序点对与Dijkstra一致”即便测试通过，也不能反证原byte权重。本批只纠正probe证据注释，不修改几何/权重表达式、road_graph或Web寻径；未来规则修复须另行授权并复核影响/回归。

额外勘误：E84B `AND DH,0F`用的是seed记录的方向byte，**不是“按tile低半字节修正方向”**。特殊首点只因tile>=D4进入该路径，方向来源见E57F写80/81/82/83。

### 军团 6.4 地图编辑的不可拆关联

节点插入、删除、坐标重排可能改变E4CE扫描号；27BE用node×4直接寻址城市，不存在名字ID映射。调整地图须一起维护city索引/坐标、四邻接、owner异属mask及1B、势力首都/AI目标、军团目标/当前位置，以及BATTLE据点目录。仅移动城市图案不产生合法道路；仅贴道路图块可能影响E961连接/特殊端点并改变全部后续point地址。

city+00低4是**紧凑邻接槽对应的异属位**，+1B是其计数，不是“有道路/城市启用”。[据点字典](re-notes-entity-fields.md#city)提供88CC双向维护及加载不重算的闭合证据；本轮原始MAP与四章邻接集合匹配是额外数据验证，不取代该指令证据。导入不改内容时保留原值；未来改变owner/邻接需同步受影响两侧，不顺手把city+1A旧所属记忆清掉。

### 军团 6.5 BATTLE目录、layout与KYOGRF页

4AF3保留city指针，4AF8..4B03由`cityPtr−0840`计算cityIdx写D34。CAEB读BATTLE.MAP头200h，CB07拿D34×2查`[layout,theme]`；CB1D再把BX还原目录号，CB21..32计算`200h + directoryIndex*1000h`，CB3E读1000h=64×64图。

实测文件D6200h=`200h+214*1000h`；有214张不同地址的地图（不声称每张像素内容都互异），不是layout三张图。城市目录0..BF；其余C0..D5为野战目录。CB44/CB56从BATTLE.MDL的`layout*100h`读100h到D308，CB59..71再从`1000h+layout*F800h`读F800h到D302；layout0/1/2选择资源块，不重编号地图。现BATTLE.MDL大小2F800h，不可据raw layout byte接受任意值。

KYOGRF据点详情页仍由city+16高半字节经7F21..7F46选`page*1200h`读1200h；实测15页0..E。低半字节为据点类型，既非战术目录也不能替代战略tile。完整类型/页显示链见[据点字典](re-notes-entity-fields.md#city)，本轮未重做景观解码。

## 军团 7. 未来编辑完整性建议（研究结论，不是实施授权）

### 军团 7.1 可作为数据基础

- 将“内容定义”“章节初始状态”“运行快照”分开：官方新章军团区为全零；已有运行槽不能只拿新章模板覆盖64B或清事件。全零只说明官方初始值，不代表KI从未读该表。
- 对DOS保留原始块及未建模byte；不要用解析字典再生成所有未知byte=0。新章的合法固定槽范围/哨兵不能替换为任意数组长度。
- 修改普通军团主将/slot关系，必须先满足全部slot与+2消费者一致性；未建立跨槽迁移算法前不能提供“任选主将”写byte按钮。势力军团数、武将状态/所属、占格、兵池都关联。
- 六队兵种/十人计数为主要输入，总兵有明确写回边界；编辑静止合法快照时必须明确同步策略，不能把任何中途差异都当bug自动修复。六队布局/空队保留槽位，未知byte不得解释为阵形。
- 目标变更、传送、地图改版是关联操作，不是几个坐标输入框。旧快照道路地址与新拓扑身份不兼容的情况下，应未来明确拒绝或做经证据验证的迁移，不自行选择最近点兜底。
- 不允许占用头3B..3F/60..7F、军团未知byte、全零事件尾存自定义扩展；无消费者发现不是unused证明。

### 军团 7.3 type10事件携带范围勘误

**实锤（布局与处理器）：** `3496 8AC4 / 3498 B4FF / 349A 8BCA`将事件AH转入AL、AH设FF、DX转CX；`349C PUSH AX → 34A1 CALL 8810 → 34A4 POP AX → 34A5 RET`显示通用TALK。`8CAE`按AH在两个文件名间选择后，共用`8CE7 MOV BX,[D56] / 8CEB XOR SI,SI / 8CED MOV DI,0400 / 8CF0 CALL E38C`读取事件块。因此SINARIO与DOS保存镜像在结构上都能携带`{type10,arg0,talkIndexWord}`，自定义SINARIO的事件区不必全零；这不是任意payload均安全的证明。

**未知（生产者穷尽性）：** 本轮及既有直接调用扫描未定位type10生产者；官方初态全零只说明数据分布，尚未完成所有间接/自修改生产闭包。旧“无KI运行时生产者、仅SAVE携带”撤销；不据此自创月结事件，也不回收全零事件区。

### 军团 7.4 DOS离线研究与当前Web架构严格分开

当前正式保存仍是浏览器同源IndexedDB `wolong-web/saves`四槽JSON；sidecar在快照内，非服务端文件。未来DOS离线研究不授权恢复旧SAVE上传API、token/lease、三文件事务，也不允许接触用户真实存档。

现行已批准边界继续适用：游戏内读档先回标题再装配，不能热替换当前scenario；空槽hover/hit-test/click全部禁用；战斗/接战过渡/待日历/未完成战略交互由保存守卫禁止快照；事务失败不得称成功；测试仅mock/内存/全新隔离profile。本研究不通过DOS缺少某字段削弱Web RNG/队列保存义务。
