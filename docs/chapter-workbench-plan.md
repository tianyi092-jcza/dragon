### P1　章节模型与命令合同（P0 后）
- 一个游戏持有共享地图、武将、城池；一章是独立可通关/失败的剧本，不继承前章。章节之下是势力及平级的武将配置、据点配置。UI 显示君主名，存稳定势力引用；君主/首都由本章任命派生。区分稳定 ID、作者可见编号、列表次序、引擎固定槽。
- 新增/改名/删章：编号与章名都是自由文本，分别限 6/8 个字；trim、统一字符计数与规范化后，分别在游戏内非空且唯一。改编号不改身份/章序；沿用同游戏复制章节能力时申请新身份及唯一编号/名称。零章可保存不可发布；删除首/中/末章不使其他有效章节失去发布资格。
- 定义原子命令而非整表覆盖。服务端在同一事务复核章/游戏归属、范围、唯一、引用和删除影响；失败不写前缀；保留现有权限、摘要/检验票失效和正式版本隔离。为旧格式制定显式读取/版本兼容策略，不在打开页面时落盘迁移。

### P2　势力生命周期与章节关系（P1 后）
- 势力编号本章从 1 自增，不显示“势力槽0”，删中间项不重排、不挪用旧引用。不扩大引擎正常槽容量；达到准入上限给出明确提示。建立势力时同存可任用君主及有效首都。换君主保留势力 ID、部下、城和钱；同章君主唯一，跨章可复用。与其他任官冲突明确拒绝或先显式解除，不自动抢人。
- 本章首都唯一且必属本势力；指定首都同步设本章当前城主，换都释放旧首都标识但保留旧城归属。只改当前所属，不覆盖原版旧所属字段。军师第一项无，其余只列本章本势力可任用的武将。移除外交官**选择项**，保留合法旧值及运行逻辑。
- 解散前列影响，取消零写入；确认后解除君主/军师、部属转自由、据点转空城、撤首都、清指向已删势力的投奔目标；审查任官、军团、外交、俘虏等残留引用，依现有证据清理或报具体冲突，不静默转给另一势力。删章另弹数量确认，一次删本章所有关系，不删主表、他章、已发版本和当前对局。
- 武将仅改本章所属、是否已登场、以月为单位的登场倒计时、预定投奔；所属可自由，投奔可无，二者独立。遵循原游戏登场及投奔规则，不另造分配算法；不得把未登场等同删除。普通据点只改本章所属，空城为有效选项。所有联动同步命名值、raw 镜像及派生计数，不能只改 DTO。

### P3　开局方案、计量与跨纪元时钟（可与 P2 分工）
- Web 新决定：每势力独立保存**玩家任军师时君主的信赖度**、税率、征兵开局方案。新建默认信赖 255、本月税率 18%、本月/下月征兵各兵种 0；未要求开放的下月税率保留原值/既有初始化合同，不补猜。新建金钱 0、作者输入 0–650000；预备骑/弓/步各默认 0、范围各 0–65000。作者输入限制不用于静默裁剪旧合法值。
- 界面一律输入实际金额/人数；两月征兵按兵种显示。仅实证以十人为单位的字段在序列化时 `floor(实际人数/10)`，显示乘 10，不能在下一层再换算。示例 127→12→120；保存前显示将保存的有效人数。金钱/预备兵各核自己的单位，禁止一律除十。测试 0、9、10、127、各字段上限与越界。
- 选择章节及玩家势力**开新局**时才把该势力方案装到运行章头；读档用快照，不重套默认值，不改原有失信/失败逻辑。以同一章两势力不同初值验证实际引擎状态，不只验表单或包 JSON。
- 作者填写公元前/公元及正整数年月日，禁止 0 年。时间始终向前：前2年底→前1年初、前1年底→公元1年初、公元1年底→2年初。沿用引擎月份/日界，不引入未经批准的公历规则。贯通日期校验、编译、计时/月结、年月显示、倒计时、存读档；跨纪元既不漏月也不重复月结。

### P4　新建与内置完整复制（依赖字段合同）
- 普通新建使用游戏自己的模板地图/据点和武将库，不凭空生成势力或原版武将。新增章可分步完成；保留已批准的空白章/同游戏复制路径。
- 完整复制逐章转换全部开局数据，按稳定人物/据点映射原槽，保留日期、两月数值、任官、特殊/保留状态；原章头只有一套方案时，以该套值初始化各可选势力，不套新建默认。历史章名长度/重复/缺编号须有确定、可追溯、不碰撞的映射，禁止无提示截断覆盖。
- **原件保留，副本纠正**：新复制时将错属首都的本章当前归属改回该势力，更新命名/raw/计数，输出修正前后明细；与此无关字段须保持。后续用户明确批准：同章同君主或不同君主共用首都时，仅保留首先出现的势力，后续在新副本丢弃并报告，不合并资源、不挪用原槽；首都不存在等其余坏引用仍报告拒绝。此决定取代原共首都一律拒绝口径，仅作用于新复制。对照转换前后编译结果和源摘要，验证未改原件、旧 copy、其他章或已发行包。

### P5　四 Tab 界面（依赖 P1/P2；可先接夹具）
