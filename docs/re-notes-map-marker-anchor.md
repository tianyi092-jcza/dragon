# 据点与行军标识图块锚点（MAP-ANCHOR-1）

## 结论与范围

**实锤**：原版16×16军团标识与所在地形图块共用左上角；不根据水平/垂直道路另加像素偏移。转向改变资源索引，不改变图块锚点。到城时规则坐标改为据点节点坐标，仍走同一叠图路径。

因此Web以中心传参、`drawImage(x-8,y-8)`绘制时，城标/军团/驻军/拾取统一为 **`(16*x+8,16*y+8)`**。道路图案本身不必穿过图块几何中心；军团相对道路的视觉偏移由原资源决定，不能再计算道路线质心、按方向补偿，或移据点迁就道路。没有“所有横路恒上移N像素、所有竖路恒左移M像素”的新公式。

用户截图用于提出假设；以下指令和资源是结论依据。旧Web统一`(+10,+11)`相比正确图块中心整体右移2px、下移3px，现已撤销。旧截图标定“水平+3Y、垂直+2X”也不再是现行合同。

### 1. 坐标入口与叠图队列

- `2AF4..2B29`先画接战，再扫描军团；`status>=C0h`调`2B2A`。
- `2B2A..2B3B`：`DX=word L10; BX=byte L12; AL=byte(L09+L08); CALL D4C7; RET`，没有像素偏移参数，也没有方向偏移分支。
- `D4C7..D4DD`减`CS:D856/D854`视口格坐标，并检查`0<=y<23,0<=x<40`。`D4DF..D4F1`计算`8*(40*y+x)`。
- `D4F3..D51E`在该8B图块记录中登记overlay索引：bit4锁定则不写，最多4个叠图；交换`record[3+count]`并递增count，索引改变则置dirty bit5。这里写的是渲染记录，非军团/导航规则坐标。无RNG、消息或方向相关坐标写回。

### 2. 地形和标识共用同一像素原点

- `87AF..87CB`将MDL及MCH分别装到`9876`及`9876+800h`段；`D46A..D482`保存同样两资源段到`D84A/D84C`。MDL图块128B，MCH图块160B。
- `D615..D669`按同一视口从384格宽的地形平面取40×23图块，写上述记录`+2`；记录步长8B。
- `D66A..D76A`逐行40格消费记录。单纯地形走`D782→D796`；有叠图时，`D6DF..D719`先以MDL图块调用`D7E7`拷入`CS:D858`的128B scratch，再逐个调用`D804`合成overlay，最后`D744→D76B→D796`提交同一scratch。
- `D7E7..D803`：MDL索引×128，原样拷64 word；`D804..D849`：MCH索引×160，16行mask先清scratch四平面相应位，然后OR后128B颜色数据；均从scratch左上角开始，无平移/裁剪/旋转。
- `D796..D7E6`每平面每行`MOVSW`写16像素并加`4Eh`，即VGA行跨度80B。`D74B..D75B`每格屏幕地址加2B，40格后再加`4B0h`，总计16行×80B。地形与overlay共享该屏幕地址，固定视口屏幕起点对两者相同，与本次世界坐标锚点无关。
- **资源复核**：MCH前24×5帧的完整16×16索引图案及32B遮罩与现有120张PNG逐像素一致（允许调色）；三种城标PNG分别与MDL `CB/CC/CD`图块逐像素一一颜色映射一致，无裁剪或平移。Web城标调色不等同原调色，不作颜色认证。
- `E4E2..E4ED`用`CB<=tile<D4`识别节点；直接解包原MMAP.MAP得到192个节点图块，其坐标集合与运行道路图192节点完全相同。`CB..D3`中有不同建筑/关卡朝向，但均为节点所在图块，不以整个多格建筑外接框另算锚点。

### 3. 转向与到城边界

- `2804..2830`通过`L0C+signed(L0A)`查下一点；先比较X，不同就写L08=西/东；仅X相同才比较Y并写北/南；两轴均相同保留原帧。斜向的X优先不按斜率或主轴长度改变。
- `27A2..27E8`由edge端点取得node；城市节点从`848h+node*4/84Ah+node*4`取城X/Y，写L10/L12及占格指针。`27E9..27F5`仅在当前node=目标node时写L08=4。随后绘制继续使用上述同格入口，没有到城像素归零或最后额外横/纵挪动。
- 48×48接战图的`2B3C..2B7F`读取描述符宽高，减去各自整除2的格数后调用D51F。既有48×48图的左上角为`16*(Lx-1),16*(Ly-1)`，中心也是`16*Lxy+8`；本次不改它的帧/倒数/声音。

## Web实施边界

- `render/mapview.js`只将两个中心常量10/11恢复为8/8，插值段定向由主轴比较改为原证的X优先；城标、驻军、选择框、拾取/吸附与接战位置沿已有共用投影同步修正。
- **保留已批准Web产品差异**：平滑插值仍覆盖`8×movePeriod`；未走完prev→current显示段时用该段定向，段尾才采用权威`_markerFrame`。DOS直接使用已提交帧，不能把Web插值时序称为原版机制。两轴为0时Web预览的驻止默认也不是对原指令“保帧”分支的替换。
- 不改`x/y/prevX/prevY`、道路点、到达条件、军团槽相位、RNG、存档或资源；不补新方向场景字段。
