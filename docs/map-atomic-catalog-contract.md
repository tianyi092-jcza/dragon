# ATOMIC-CATALOG-1：单格素材库与单层分类

## 1. 用户决定与范围

**Web 产品决定（非原版机制）**：用户在SEA-GROUND-1之后要求素材库全部直接使用原游戏16×16单格图块，不再展示组合样板；取消「基底／装饰／道路／据点」一级库导航及「分类样板／原始历史／我的素材」等库切换，只保留末级分类。后续追加水路、桥梁归道路；底图自然露出，不需要用户理解或手工铺设“海域”；去掉素材悬停说明。

本文件是这轮素材库的详细维护源，替代第二阶段及SEA-GROUND-1中的**素材库导航／默认组合卡／Tooltip**约定。全幅95底图、地面小地图贡献及共同编译仍由[SEA-GROUND-1](map-sea-ground-contract.md)维护。旧v41资源／身份审计和历史验证不是新库的验收结果，也不因本轮展示调整失效。

最初原子库批次不包含：自动拆除地图上的现有组合、删除旧定义或实例、新建道路／桥梁／水路、移动据点或自动势力配色、地图扩容、生产迁移。后继用户批准的已有道路／据点对象移动见§2.7，不再沿用旧移动禁令。共同组合／拆分能力保留；后继MAP-SPACE-4按用户要求把右键菜单的组合／打散入口暂置禁用，不自动拆旧对象，也不开放新的据点组合工具。

后继用户已批准新增[四种据点组素材](map-city-group-contract.md)，这是对“不展示组合”的明确专项追加。现已按后续“先放面板看看”要求接入四张只读组合预览，在据点后新增据点组TAB；工作台为240单格＋4组／八类，放置／拆散仍未开放。组合尺寸与展示边界详见[据点组合同](map-city-group-contract.md#readonly-library)。

### 2.5 MAP-PAN-LOCK-1：地图拖动锁定切换

**用户批准的Web交互决定**：顶部锁图按钮切换锁定／解锁，锁定后地图不能拖动，作为后续地图对象操作的基础。此锁不是图层锁或对象锁，不扩展为禁止选取、缩放或编辑。

- 每个地图面板实例默认解锁。按钮正常可用（无地图或工作台忙时禁用），以开锁／闭锁图标、`aria-pressed`和悬停提示反映状态；鼠标点击、Enter／空格均可切换。
- 锁定时仅阻止Canvas指针拖动调用平移动作；仍记录移动阈值，拖动松手不能误当作单击选择另一格。切换锁定清除当前拖动手势，解锁后必须重新按下才能开始新拖动，不续接旧指针移动。
- 单击选取、右键／Shift+F10菜单、全图／放大／100%／缩小和滚轮缩放仍工作；素材拖放、图层眼睛／锁和浮动工具移动仍按原规则。对象权限、图层锁及既有禁用入口不因锁图而放宽。
- `panLocked`仅是`BaseMapPanel.vue`本地显示状态，模板与作者游戏共用此交互；不发保存命令、不改变dirty／undo，不写source、copy或本机持久存储。同一面板保存重读、撤销和导航折叠／窗口改变保持该状态，重新挂载面板从解锁开始。未实现任何新的对象移动／组合／变换能力。

### 2.6 地图交互收尾：选位背景与锁图对象操作

**Web产品决定（非原版机制）**：用户在journal §188批次明确未锁拖整图、锁定拖选中对象、点击切换选择；本次接续再次确认“底图格如果有作用，就让它发挥作用”“底图格仅这点作用即可”。以下覆盖§2.3／§2.5的旧禁用边界：

- 未锁时拖整图；锁定时允许拖已选且可编辑的装饰／组，以及§2.7开放的道路／据点对象，空白或Shift手势不回退为拖整图。图层锁仍独立生效。拖动开始后原位不再绘制选中对象，实体以50%透明度随鼠标移动，保持抓取点相对位置；组合／多选同样处理。预览不修改源与规则图，落定才一次提交；Esc／丢失捕获恢复原位。点选仅拾取当前最上层对象，不穿透选取被覆盖装饰。
- 点击装饰／组切换选中，再点同一对象取消；Shift多选允许组合／拆散，单个已有组也可拆散。底图格仅提供新据点放置坐标，不是装饰对象，不开放移动、组合、拆散、删除或右键／Shift+F10对象菜单；诊断定位仍可标记底图坐标。
- **新组合为独立对象（用户确认，兼容历史）**：多选超过一个对象时组合／拆散均可用；组合将所选历史通用组／多格片段按单格图块展开，再依原绘制顺序合并为一个新装饰实例，系统生成实例及内部配方ID，不新增`selectionGroups`关系；重叠格保留所选对象中最上层图块。历史所属组合数据仍兼容，但界面不显示“所属组合”。整批一次预演／撤销／保存，拒绝专用据点／水系组改写；混合不兼容水域类别仍遵共同配方拒绝门。新对象可超过256格，以地图格数为单对象上限（普通素材擷取仍限256格），拆散走同范围且仍受4096条／16 MiB整批预算限制。
- **多选删除**：Shift多选后右键删除可用，批量删除所选装饰／通用组成员，不影响被覆盖但未选中的对象；一次撤销恢复整批。
- **工具位置（用户截图确认）**：缩小按钮后依次为锁图、复制、填充三个图标；复制／填充仍暂未开放，只移动入口。右键操作第二行改为组合、拆散、对象锁、删除；对象锁仍暂未开放。单格对象也允许点击拆散，结果为无修改。
- **拆散到单格（用户接续批准）**：选择组合或多格装饰片段后，“拆散”一次解除选中通用组合关系，并将成员中支持的多格装饰用既有`decoration-split`拆成独立单格；已经没有所属组合的多格片段仍可拆。纯单格组合只解除组关系，单格本身不重复拆。整批预演／一次撤销，失败不安装部分结果；缺受信原子、专用据点／水系组或超出既有限额时拒绝，不猜配方、不绕过权限、不后台全量迁移。
- **保存容量（用户批准增大）**：地图未保存修改累计最多4096条命令、完整JSON请求最多16 MiB；共享常量为`web/src/editor/mapeditlimits.js`。前端预览、基础地图store、copy地图命令门及HTTP/TLS运输层保持一致；只提高`POST /api/admin/base-map/save`与`POST /api/games/<uuid>/copy`的请求体上限，其它接口仍16 KiB。copy接口承载多个模块，模块权限／字段校验不变。一次拆散仍一次撤销，超限原子拒绝，提示区分积累修改与单次操作过大。不是全量地图／无限命令承诺，也不改变64 MiB模板／copy源限制。
- 分裂保持每格原位置、图块、地理及小地图语义；保存重读后按不同子实例ID逐格选择，子实例可再组合／拆散。只核验所属组合文字消失不足以验收，须检查原多格实例不再存在且每个子实例占一格。详细验证见journal §191。
- 拆散提示复用已有状态区，不另加会改变画布尺寸的提示节点；右键保留提示，左键及载入／保存／撤销清提示。避免提示变化令画布重排、菜单消失或点击落格偏移。
- 游戏地图的“建城”入口位于工具栏，使用默认ElDialog容纳原新据点表单；不再把表单常驻地图下方挤占画布高度。先在地图选格，再打开建城操作；关闭弹窗不清除表单输入。基础模板不出现建城入口。
- 当前工作台浏览器总入口运行现行显隐／地图布局与锁图／选择拆散／新城四个专项；原draft/Trial历史体保留在`--legacy-draft`，不再用其旧控件断言现行产品，不宣称覆盖等价或历史套件通过。执行证据见journal §190。

### 2.7 道路／据点拖动与保存时错误详情

**Web产品决定（非原版机制）**：用户在§193后明确要求已有道路、据点也能拖动；最终澄清为“拖放后只标红，只有保存时才列对象ID、据点名称／ID、坐标和原因”。本节为现行唯一详细源。

- 沿用未锁拖整图、锁图后拖已选对象。道路平移其明确的`geometry`和`components`，同步原道路bounds；据点平移中心以及显式`city-group-<cityId>`的装饰成员，不根据相邻城墙或图样猜归属，不自动拉伸／重连相邻道路。ID、端点城市引用、槽号、章节邻接及战场绑定不重编号。50%实体预览、抓取点、一次撤销、取消及图层锁保持一致；整体越界不安装候选。
- 新受限命令为`map-object-translate {layer,id,dx,dy}`。前后端共用`mapobjectmove.js`；据点坐标同步共享主表与全部章节具名X/Y、已有32B raw的`+08/+0A`小端word及已有重复raw表，其它byte不动，不补未知raw。此处复用[实体字段原证](re-notes-entity-fields.md)据点表（`3F43/27C2` X、`3F2C/27C6` Y）；没有新增原版机制结论。
- 拖放安装候选后立即用`mappositionvalidation.js`复核。失败格绘制35%透明红色覆盖；同格只画一层，修正或撤销后重新计算并解除。位置问题仅保存在Canvas私有显示状态，不写入内容、Vue错误列表或小地图，也不在拖放时弹出对象／据点／坐标／原因文字。
- 保存时使用同一校验，仍有位置问题则拒绝请求／持久化，保留待编辑内容与红罩；错误区这时才列对象ID、相关据点名称／ID、格坐标与原因，并提示保存失败、请检查。已知拒绝不锁死工作台。服务端独立复核，不能绕过前端强存；成功仍走原编译／事务／重读。
- 校验复用既有道路构造合同（端口、点列、图块、重叠／交叉、方向槽）及连通门，并检查重叠节点、中心覆盖和既有稠密扫描槽序；原认证方向／路格不符也拒绝，不猜道路或自动修复。改变节点扫描次序目前须调整位置解决，本批不授权重排所有章节身份。合规实例可保存，不是“一律禁止移城”。
- **范围隔离**：检查模式随本批未保存的移动命令存在；该批后续修正也持续复核。撤销全部移动、保存重读、换源会清除该模式。既有copy“建档→stamp→bind→admit→接路”的分步中间态保存不因此新增全局拒绝门；这不是关闭移动批次的校验。模板原有完整编译门不变；不扩展到道路／据点的Shift批组／批删或任意拓扑编辑。
- 本地回归及明确未验证项见journal §194；不代表生产部署或用户库已修改。
