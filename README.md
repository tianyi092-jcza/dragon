## 项目概况

《卧龙传》是 NEO·GETEN 制作、松岗中文化发行的三国题材战略游戏，日文版于 1994 年推出，繁体中文版于 1995 年发行。与以君主为中心的传统三国游戏不同，玩家以军师身份参与势力经营、人才任用、外交与战争决策。

本项目参考原版程序、二进制数据和图像／音频资源，重新实现浏览器端规则、内容加载、交互与渲染。目标是保留军师视角和即时战略体验，同时重新组织大地图、战场和现代浏览器界面。历史背景参考维基百科；具体机制以可复核的原始证据为依据，不把百科、截图或当前实现当作原版规则证明。

### 当前内容与特点

- **20 个内置章节**：包含原版及上、中、下、后四组改版章节，共五组，每组四章；共享同一套规则与界面内核。
- **战略经营与战争流程**：据点、武将、人事、编成、内政、外交、行军、接敌，以及野战／攻城和战后接续。
- **大地图整体呈现**：将地图图块与分层对象组织为可拖拽的大场景，不再以零散画面理解地图。
- **原生开场**：独立开场动画、资源加载进度、跳过流程与开场音轨。
- **本地多存档**：玩家使用浏览器 IndexedDB，单档与摘要分离；支持独立管理页的 JSON 导入导出。玩家无需登录、没有云存档；编辑器后台另有账户及数据库，不保存玩家对局。
- **静态自托管**：无需框架、打包器、npm 运行时依赖或原版安装目录；可部署到普通静态服务器、Cloudflare Pages 或 Workers Static Assets。

- **全屏体验**：使用 F11 开启浏览器全屏，效果更佳。

### 与原版呈现不同的部分

| 项目 | 当前 Web 版 |
| --- | --- |
| 战略大地图 | 384×256 格组成 6144×4096 像素整体地图，固定比例显示，拖拽平移；保留战略小地图定位、势力与军团信息。 |
| 战术大地图 | 将完整 64×64 等距战场合成为 2048×1088 大场景，使用相机裁切与拖拽；地形、人员、效果分层，配合六队卡栏和命令浮窗。 |
| 地图“合并”的含义 | 分别整合战略地图和战术地图的完整场景，**不是把战略与战术合成同一张无缝世界地图**；二者仍有独立规则和场景切换。 |
| 操作与计时 | 右键逐层返回；军师子菜单锁定地图。战略地图鼠标移动时暂停，连续静止 1 秒后按其它暂停条件决定是否恢复。 |
| 战术界面 | 当前不显示战术小地图和右下双箭头；不支持通过点击空白地面下达任意坐标移动命令。 |
| 统一之后 | 继续战略地图，尚未接入新的统一通关动画；原结局素材保留，失败 GAME OVER 流程仍在。 |

这些是 Web 产品呈现与交互决定，不构成“原版完全如此”的声明。项目仍在逆向核对与回归完善中，不宣称全部 DOS 机制或像素级表现完全等价。现已有现容量编辑工具、组件／道路创作工作台和独立编辑后台；创作能力不等于运行准入。地图扩容、任意移城／新拓扑的完整运行、任意内容包热切换、多语言和新的通关过场尚未完成。

## 快速开始

需要 Git、Python 3，以及支持 ES Modules、Canvas 2D、IndexedDB、Web Audio 的现代桌面浏览器。

```bash
git clone https://github.com/tianyi092-jcza/dragon.git
cd dragon
python -m http.server 8321 --directory web
```

打开 <http://localhost:8321/>。不要直接双击 `index.html` 使用 `file://` 打开。

- 推荐桌面 Chrome／Edge 等现代浏览器；完整触屏操作与跨浏览器兼容性尚未全面验证。
- 鼠标拖拽平移地图，左键选择据点／军团与菜单，右键逐层返回；部分强制交互不允许右键取消。
- 浏览器可能要求首次点击后才能播放声音。没有声音时先检查网站静音、音效设置及自动播放权限。
- 存档绑定浏览器配置与网站源（协议、域名、端口）。更换域名、无痕窗口或清除网站数据不会自动迁移存档；项目不提供云同步。
- 游戏内读取存档先回到标题流程。请勿把原版 DOS 存档复制到网站目录。
- 独立工具：[存档管理](web/saves.html)（运行时 `/saves.html`）、[早期受限编辑器](web/editor.html)（`/editor.html`，导出副本补丁）。完整编辑后台不是这个静态页面，见下节。

## 游戏编辑器

编辑器面向桌面浏览器，内部界面采用繁体中文，用户输入保留原文。**当前是持续开发中的工具集，不是已完成、已公开部署的创作平台。** 内置游戏受保护，编辑操作作用于独立副本，不修改正在运行的对局或玩家存档。编辑器为 12 项扁平菜单（游戏组在前、管理组在后），品牌为“卧龙传编辑器”；展示层统一用 Element Plus 默认主题与默认组件（Web 产品决定，非原版机制）。

### 功能与边界

- **独立编辑后台**：12 项扁平菜单覆盖游戏管理、章节工作台（章节管理、势力设定、势力武将、势力据点、外交关系）、武将主表、据点属性、共用头像库、地图工作台、校验／发布与管理员上下架。游戏管理负责上架发布，删除游戏只在上架审核入口；内置游戏不可编辑、下架或删除。每款游戏只有一套可编辑副本、一个发布槽、一份正式快照；普通新建与完整复制分开，只允许一个成功的完整复制基准。共用头像库 621 张（`0..620`）只读，不接受上传。仅开放已支持的字段与操作，不代表所有设计表单已经实现。
- **地图创作工作台**：系统模板与游戏副本共用单格命令、权限模型与写入校验，但写入对象各自独立。单格源（`cell-map-1`：每格一个 LE16，`256` 为空、`0..255` 为素材）已接通工作台、保存、编译与玩家发布路径；地形、规则地理、小地图地理、路网分开存放。纯装饰直接保存；凡动过道路／城池即做路城校验，`buildRoad` 只认证两座已绑城市间唯一门到门路链，残段标红并拒写。Shift 拖动只复制装饰，移城保留身份及章节槽，`Ctrl+Z` 按手势撤销。道路绘制不等于获得可运行通路，断路、残段和超域数据会被运行／发布检查拒绝。
- **据点与武将**：据点先建档（指定战场与城兵上限初值），再到地图放置、绑定、连路；战场、城景与上限是不同字段。改名、改州郡或改数值不重算道路、不编译地图；删城仍查落点、路端与章节引用，发布时全量校验。武将主表以稳定 ID 关联章节槽，删章不影响主表或其他章节。
- **试玩与发布**：旧 `/api/trial/*` 已退役（`410`），保留引擎不代表重新开放服务；以工作台校验后的同引擎加载为准，不读写正式存档。副本保存只拦模块约束，发布时全量校验；提交须同摘要一次性票据＋说明并节流，审核同意在同一事务配发不重用的版本并更新版本／快照／上架。内容发布与 Git／程序部署是不同流程；正式版更新会使旧局禁存、旧档不可载入。
- **仍受容量与原证限制**：原域仍为 384×256，系统模板与游戏地图支持四向扩缩（每侧 `0..40` 格，最大 `464×336`，不裁原域、不移旧坐标；新增只复制当前边线普通地形及叠层，不复制道路／桥／城门或据点），但工作台未开放扩缩操作。据点容量与地图尺寸是不同准入门，内置与生产限制见[CITY 计划](docs/city-capacity-expansion-plan.md)。完整物理删除、部分字段／浏览器流程及跨平台上线仍未完成；详见[开发待办](docs/editor-dev-todo.md)、[单格地图合同与转换命令](docs/single-cell-map-migration.md)与[扩缩验收边界](docs/map-expansion/acceptance.md)。

### 本地启动认证后台

需要 Node.js 22.13+（或较新的受支持版本）与 OpenSSL。以下命令只启动本地开发环境，不部署生产服务、不自动安装依赖：

```bash
# 启动本地编辑器（状态目录隔离，勿指向生产数据）
node tools/dev_editor.mjs --port 8443 --store .dragon-analysis/basemaps-dev-store
# 改过 editor-ui 后先构建再检查，并同步产物与授权清单
node editor-ui/build.mjs
node editor-ui/build.mjs --check
```

打开 **<https://127.0.0.1:8443/play>**（仅重定向到独立玩家站，默认 `https://127.0.0.1:8444/`）。初始管理员为 `tianyi`，首次登录须改密。`8321` 只供静态引擎验证；本地分发桶与生产隔离，旧 pin 不等于正式分发历史。Vue 改动先 `build` 再 `--check`；改过 `server/public/*.txt` 或 `web/src/**` 后重启自己持有的实例并核对实际服务字节，不停止他人进程；端口占用时先处理自己的服务。

- 本地开发状态目录与生产数据隔离，重启不等于清库，备份时须单独保护这些数据，均不入 Git。
- 构建、语法检查与服务刷新是三件事：`build ≠ check ≠ 服务刷新`，发布归档以完整 inventory／SHA 与 pin 为准，不放宽冻结身份。
- 生产为玩家／编辑器分服务部署，操作前按[存储布局](docs/game-storage-layout.md)核对主机、目录、程序与 pin，不沿用旧进程或远端状态；提交、推送、部署、真实数据迁移各自另行授权。

## 部署

### 私有化／自托管

完整 `web/` 可以独立运行。推荐用 Node.js 22 或更新的受支持版本生成精简发行目录：

```bash
node tools/prepare_deploy.mjs
python -m http.server 8321 --directory dist
```

该步骤只复制发布资产、不编译游戏代码、不读取原版目录。每次运行会重建仓库内的 `dist/`。音频研究材料、调试输出和说明截图不进入发行目录；结束画面仍保留。

生产环境将 `dist/` 内容作为站点根目录，经 HTTPS 提供服务。若仅供私人访问，须在反向代理或 Cloudflare Access 中配置访问控制；**自托管和私有 Git 仓库本身不等于网站已限制访问**。详见[部署指南](docs/deployment.md)。

### Cloudflare Pages：推荐自动部署

在 Cloudflare 控制台创建 **Pages → Connect to Git** 项目，授权 GitHub 仓库，使用：

| 配置项 | 值 |
| --- | --- |
| 生产分支 | `main` |
| 框架预设 | `None` |
| 仓库根目录 | 默认仓库根，不填 `web` |
| 构建命令 | `node tools/prepare_deploy.mjs` |
| 输出目录 | `dist` |
| Node.js | `22`（可设置 `NODE_VERSION=22`） |

连接后，每次推送 `main` 触发生产部署；预览分支行为在 Pages 项目设置中管理。无需将 Cloudflare 密钥写入代码。

### Cloudflare Workers Static Assets：可选

玩家静态站使用根目录 `wrangler.jsonc`，该配置没有 Worker 服务端入口，也不需要数据库（不要与 `server/wrangler.jsonc` 的编辑后台混淆）：

```bash
npx wrangler@4 login
npx wrangler@4 deploy
```

部署前确认目标账号与项目名，避免覆盖同名项目。CLI 会执行静态打包命令。Workers Git 自动构建、Pages 首次授权、自定义域名、缓存、404 和私有访问配置见[部署指南](docs/deployment.md)。

## 开发结构

```text
web/                  可独立运行的静态游戏
  src/                规则、导航、场景、渲染与 UI
  content/builtin/    可编辑章节与世界内容源
  intro/              原生开场场景
  grf/                游戏图像、音频及部分逆向证据
  kao/                武将头像
server/               认证编辑后台、草稿／Trial／发布服务及工作台页面
vps/                  Node／SQLite 适配与发布工具（正式迁移未完成）
reader/               Cloudflare 只读分发原型（未上线，不可直接生产部署）
tools/                本地启动、离线导入、编译、分析及回归工具
docs/                 架构、原始证据笔记、部署说明与截图
dist/                 自动生成的玩家静态发行目录（不提交）
```

玩家浏览器运行不要求 Python 或 Node.js；它们用于本地服务、离线工具或发布。编辑后台是独立服务，另有 Node／workerd、SQLite 及资源存储要求；静态站部署命令不会部署后台。内容生成工具可能额外依赖 Pillow，浏览器回归需要 Playwright；这些不是产品运行依赖。内容管线详见[内容架构](docs/content-architecture.md)，维护约定见 [AGENTS.md](AGENTS.md)。
